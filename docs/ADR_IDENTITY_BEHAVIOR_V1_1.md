# 九章 WDSP 身份与行为防护 V1.1 ADR

## 目的

记录 V1.1 身份识别、枚举检测和管理面契约的实现决策，避免开发任务拆分与现有 WDSP 数据面产生隐式冲突。

## 决策

1. **复用现有链路**：身份解析复用 `RequestContext` 与 `jiuzhang_guard` 请求处理链，事件仍通过 `identity-events.log` 断点采集器入库；不新增旁路网关或网络调用。
2. **身份类型与置信度**：管理面统一类型为 `HUMAN/BOT/APPLICATION/SERVICE/AGENT/UNKNOWN`。`MACHINE` 是历史兼容值，旧数据在查询时归一为 `UNKNOWN`，不再出现在新增数据、筛选项或接口枚举中。置信度为 0–100，证据仅保存脱敏标签，禁止记录 token、Cookie、原始账号/对象值。
3. **枚举检测**：账号/对象标识值使用 HMAC 脱敏后进入有界集合计数；分页字段本身的变化不计入标识轮换，但携带分页参数的请求仍照常提取账号/对象标识（防「&page=1 即免疫枚举检测」一键绕过）；批量/同步/导出路径段（batch/bulk/export/replication/sync）整体跳过标识提取——伪造路径段会改变路由，不构成免费绕过。计数超过策略阈值后只生成 `OBSERVE` 信号，不直接阻断。
4. **兼容与容错**：新增字段采用幂等迁移并提供默认值；网关行为策略关闭或 Valkey 不可用时保持 fail-open，旧事件/旧配置可继续读取。
5. **版本与回滚**：身份契约字段由迁移 `000116` 管理，行为策略及事件扩展由 `000117` 管理；下行策略携带版本号，回滚仅回滚配置快照，不恢复敏感证据原文。
6. **模式职责**：`security_behavior_policy` 的 `mode` 固定为 `OBSERVE`，仅控制行为检测与信号生成；`security_risk_policy` 才允许 `OBSERVE/PROTECT`，并由 Risk Engine 统一执行限速或阻断。管理端不得把行为策略的检测模式展示为实时阻断开关。

## 非目标

V1.1 不开放行为信号的阻断动作、不引入新的身份存储基础设施，也不改变既有 CC/WAF 规则优先级。

## 已知限制

1. **identity_key 凭据优先且凭据未验签（LOW-G5）**：`identitybehavior/identity.go` 的身份键按「凭据 > 浏览器指纹 > IP」优先级确定，而网关上观察到的 API Key/OAuth/JWT/Cookie 均未经网关验签（仅 mTLS 客户端证书为已验证强凭据）。攻击者轮换凭据值即可得到全新 identity_key，重置按身份维度的行为累计（枚举计数、侦察信号分值、风险评分）。该限制由 IP 维度的 CC 频率限制、临时封禁与 WAF/Coraza 检测兜底——按身份的行为信号在本阶段仅为 OBSERVE，不单独作为阻断依据；待网关具备应用级凭据验签能力后再提升凭据身份的置信度与处置权重。
