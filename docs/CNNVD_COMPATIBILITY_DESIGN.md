# WAF 规则 CNNVD 兼容性设计（兼容性认证支撑）

版本：v1.0（方案评审稿）
状态：待评审

## 1. 背景与认证要求

CNNVD 兼容性认证（中国信息安全测评中心）的定义：「通过使用 CNNVD 标识，在各类安全工具、漏洞数据存储库及信息安全服务之间，以及与其他漏洞披露平台之间，实现漏洞信息交叉关联」（[CNNVD 官网](https://www.cnnvd.org.cn/home/service)）。防火墙/安全运营平台/WAF 类产品均有认证先例。

对本产品（WAF）的落地含义——形成「**漏洞编号 ↔ 防护规则 ↔ 安全事件**」的交叉关联链：

1. 规则可使用 CNNVD 标识（`CNNVD-YYYYMM-NNNNN`）规范化标注，同时支持 CVE 编号对照；
2. 事件命中规则后可呈现关联的 CNNVD/CVE 编号（标准化描述载体）；
3. 支持按漏洞编号交叉检索（编号 → 规则 → 事件；事件 → 编号）；
4. 输出物（事件导出、报表）携带 CNNVD 编号。

**非目标**：不接入 CNNVD/CVE 官方数据同步（此前已决策不做漏洞库同步）；不做漏洞扫描；不改变规则检测逻辑本身。

## 2. 数据模型（迁移 000167）

### 2.1 规则编号字段

- `waf_rules`（CRS 规则目录）与 `custom_rules`（自定义规则）各加两列：
  - `cnnvd_ids JSONB NOT NULL DEFAULT '[]'` — CNNVD 编号数组，如 `["CNNVD-202401-2345"]`
  - `cve_ids JSONB NOT NULL DEFAULT '[]'` — CVE 编号数组，如 `["CVE-2024-0001"]`
- 格式校验（服务端）：CNNVD `^CNNVD-\d{6}-\d{3,}$`；CVE `^CVE-\d{4}-\d{4,}$`；去重、大写归一。
- 索引：`GIN(cnnvd_ids)`、`GIN(cve_ids)`（按编号反查规则）。
- 规则版本/快照语义沿用现状（custom_rules 直接改；CRS 目录规则的编号标注挂在 `waf_rules` 目录行上，随目录版本留痕）。

### 2.2 漏洞条目本地档案表（小表，手工维护）

`vuln_refs`：`id`、`cnnvd_id UNIQUE`、`cve_id`、`title`（规范中文名）、`severity`、`published_at`、`url`（CNNVD 官方条目链接）、`created_at/updated_at`。
用途：认证演示与日常运营时，编号可展开为规范名称与官方链接（「规范性命名与标准化描述」的直接证据）；数据由管理员在界面手工录入（认证涉及条目量级小，无需同步通道）。

## 3. 接口与界面

### 3.1 规则侧

- 自定义规则创建/编辑/详情：新增 CNNVD/CVE 编号字段（多值标签输入，格式即时校验）。
- 规则列表（自定义 + CRS 目录）：支持按编号精确检索（`?cnnvd_id=` / `?cve_id=`）；列展示编号标签（悬停显示 vuln_refs 规范名称）。
- 漏洞档案页（新，轻量）：vuln_refs CRUD + 每条档案的「关联规则」「关联事件」计数与跳转。

### 3.2 事件侧

- `security_event_matches` 已记录 rule_id/rule_source/rule_version——事件详情「命中规则」区域追加该规则的 CNNVD/CVE 编号标签（联查规则目录，编号缺失时静默不显示）。
- 事件列表（可选列/筛选）：按 CNNVD 编号筛选事件（命中规则带有该编号）。
- 事件导出 CSV：新增 `cnnvd_ids`、`cve_ids` 两列（命中规则编号并集，分号分隔）。

### 3.3 交叉查询接口（认证演示核心）

- `GET /api/v1/waf/vuln-refs/{cnnvd_id}` → 条目 + 关联规则列表 + 近 30 天命中事件计数/样例。
- `GET /api/v1/waf/rules?cnnvd_id=...` → 规则视角反查。
- 权限：读沿用 `waf_rule.read` 族；档案维护新增 `waf_rule.vuln_ref.edit`（命名随现有风格，三角色按惯例分配）。

## 4. 认证演示路径（测试用例直接可用）

1. 录入漏洞档案（如 CNNVD-202401-2345 / 对应 CVE）；
2. 给一条自定义虚拟补丁规则标注该编号；
3. 构造命中该规则的攻击请求 → 事件详情显示 CNNVD 编号 + 规范名称 + 官方链接；
4. 按编号反查规则与事件；导出事件 CSV 展示编号列；
5. 全程审计留痕。

## 5. 实施阶段

**P1（本期）**：迁移 + 自定义规则编号字段读写与校验 + 列表检索 + 事件详情编号展示 + vuln_refs 表与 CRUD + 交叉查询接口 + 前端（规则表单/列表/事件详情/档案页）+ 测试 + stage5 端到端演示数据（1 条档案 + 2 条标注规则 + 命中事件）。
**P2**：事件导出 CSV 编号列、安全报表「漏洞防护覆盖」章节、CRS 目录规则批量标注工具。
**P3**：编号格式在线核验（CNNVD 官网链接可达性检查）、认证材料一键导出（规则-编号-事件关联清单）。

## 6. 测试方案要点

- 编号格式校验矩阵（合法/非法/大小写/重复）；
- 检索正确性（GIN 索引命中、空编号不过滤）；
- 事件详情联查：规则删除/编号变更后事件侧表现（编号取查询时现值，快照语义写注释）；
- stage5 E2E 走通 §4 演示路径。

## 7. 决策点

| # | 问题 | 选项 | 建议 |
|---|---|---|---|
| 1 | 编号存哪 | A 规则行 JSONB 数组 / B 独立关联表 | **A**（规则数小、随规则导出快照自然；GIN 索引足够） |
| 2 | 漏洞条目档案 | A 手工维护小表 / B 不接条目只存编号 | **A**（认证演示需要规范名称与链接，几十条量级手工够） |
| 3 | CRS 目录规则标注 | A 支持（P1 就带）/ B 仅自定义规则 | **B 先做自定义规则，CRS 目录标注放 P2**（CRS 多为通用攻击型规则，无具体漏洞对应，认证价值低；避免目录同步时被覆盖的语义问题） |
| 4 | 事件编号口径 | A 查询时联查现值 / B 事件落库时快照 | **A**（编号标注会演进，现值最准；matches 已有 rule_id 可联查） |
