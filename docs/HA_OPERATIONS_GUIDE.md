# 主备高可用部署与运维手册（HA Active-Standby）

> 适用：docs/HA_ACTIVE_STANDBY_DESIGN.md 的 M1-M4 已落地能力——
> 网桥端口联动（Link-Pair）、主备 VIP（keepalived 封装）、TLS 会话票据共享、HA 状态告警。
> 读者：交付工程师与现场运维。设计原理与边界声明见设计文档，本文只讲怎么做。

---

## 1. 部署清单（主备最小落地）

### 1.1 前置条件

| 项 | 要求 |
|---|---|
| 网关节点 | 两台同版本镜像主机（digest 锁定），裸机/虚拟机推荐；keepalived 容器化运行需 `NET_ADMIN` |
| 网卡 | 串接部署每节点至少 2 个业务口（成对进桥）+ 1 个管理口；业务口**不得预配 IP**（收入桥安全红线） |
| 上游设备 | 防火墙/交换机按链路通断选路：默认链路 A、故障切链路 B（具体配置属上游厂商，非本系统） |
| 基础设施 | 共享 PostgreSQL 主库、共享 Valkey（计数/行为/会话状态；**必须**显式置 `behavior_store=valkey`） |
| keepalived | 网关节点系统包安装（版本兼容矩阵见 §5 已知边界）；组播被禁环境用单播 VRRP |

### 1.2 部署步骤

1. **网关节点**：同版本部署两节点，`gateway_node` 各唯一（如 `gw-a`/`gw-b`），havipd 与 netmgrd 随节点驻留运行；
2. **节点登记**：管理面「API 防护 → 节点校验」确认两节点心跳 ACTIVE；分别 PATCH 登记 `admin_addr` + `sync_enabled`（发布扇出前提）；
3. **共享状态**：系统设置 `gateway_runtime` 组确认/写入：
   - `behavior_store = valkey`（判定态共享，主备切换 CC/封禁连续的前提）
   - `identity_salt`（身份指纹盐，两节点一致——随发布下发，无需逐节点配置）
   - `tls_session_ticket_key`（可选但强烈建议：64 位 hex，`openssl rand -hex 32` 生成；主备 TLS 会话恢复前提）
4. **网桥与联动**：「系统运维 → 网络配置」建桥（成员口恰 2 个）→ 开启「端口联动」并按需调整参数（故障判定 1000ms / 恢复判定 5000ms / 每小时上限 20 次为缺省）→ 保存下发；
5. **主备组**：「系统运维 → HA 主备」新建组：VIP（CIDR）、VRID（同二层域唯一）、两成员节点与优先级（高者为主）、抢占默认关（`nopreempt`，主恢复不自动回切）、可选 VRRP 认证串（≤8 字符）→ 保存并下发；
6. **验证**：按 §3 交付检查项逐项过一遍（重点：拔主节点一根网线 → 对口联动 down、上游切链路、VIP 漂移 ≤5s、业务会话不中断）。

### 1.3 上线前红线核对

- [ ] VIP 承载网卡不是任何网桥的成员口；
- [ ] 桥成员口均无 IP 地址（有 IP 会被执行端安全拒绝）；
- [ ] `behavior_store=valkey` 已生效（一致性视图/节点状态页可见）；
- [ ] 两节点配置一致性视图 consistent=true（「节点校验」页）；
- [ ] 通知渠道已订阅「基础设施」类别且级别覆盖 MEDIUM（HA 告警才收得到，见 §4）。

## 2. 运维手册（日常操作）

### 2.1 状态查看

| 看什么 | 在哪看 |
|---|---|
| VIP 当前在哪台、keepalived 是否存活、漂移时间线 | 「HA 主备」页运行状态卡 |
| 端口联动态（正常/已联动 down/已抑制）、故障口 | 「网络配置」页执行状态卡 |
| 两节点配置一致性 | 「节点校验」页 |
| HA 相关系统告警 | 「系统管理 → 系统告警」（类型见 §4） |

### 2.2 常见操作

- **人工回切（主备切换演练/计划内维护）**：「HA 主备」组行「回切」→ 确认。语义：交换两成员优先级并重新下发，VIP 随选举切换；切换瞬间在途长连接断一次（客户端自动重连），用户**不需要重新登录**。
- **端口联动抑制复位**：抑制态说明物理链路在抖动（1 小时内联动超上限）。先查线/光模块，再在「网络配置」页**原样保存一次**该节点网络配置即复位（无需改参数）。
- **联动误触发恢复**：故障口恢复后配对口会在恢复判定窗口（默认 5s）后自动回 up，无需人工干预；若配对口是被运维手工 down 的，系统绝不会自动拉起（联动标记保护），需人工 `ip link set <if> up`。
- **VIP 认证串/票据密钥轮换**：改系统设置（`ha_groups` 编辑认证串 / `gateway_runtime.tls_session_ticket_key` 换值）→ 触发发布 → 全节点一致生效。票据密钥轮换会使旧票据失效一次（回退完整握手，不掉登录态）。
- **停用主备**：组编辑为 DISABLED（实例停止、VIP 释放、配置保留）；删除组 = 收回能力（havipd 停实例释放 VIP 后删配置，二次确认）。

### 2.3 故障处置矩阵

| 现象 | 含义 | 处置 |
|---|---|---|
| 告警「端口联动触发」 | 某桥一口链路故障，配对口已联动 down，上游应已切备链路 | 查故障口物理链路（线/光模块/对端口）；恢复后自动回 up |
| 告警「端口联动抑制」 | 链路抖动，联动超上限已冻结 | 先修物理链路，再原样保存网络配置复位 |
| 告警「主备VIP异常」 | keepalived 不存活/FAULT/havipd 停止 | 节点上看 havipd 日志与 keepalived 状态；修复后自动恢复 MASTER/BACKUP |
| 告警「网络配置执行失败」 | 网桥/路由执行失败（如成员口带 IP/不存在） | 按告警 message 修正配置或接口状态，保存后自动重试 |
| 页面状态「未上报」 | 对应执行端（havipd/netmgrd）未运行 | 节点上拉起执行端；状态随后自动上报 |
| 双 MASTER（脑裂告警） | VRRP 通告链路中断 | 恢复通告链路；确认业务不受影响后人工回切收敛 |

### 2.4 切换对会话的影响（如实口径）

- 应用登录态（cookie/token）：**不受影响**，用户不需要重新登录；
- 管理控制台会话：**不受影响**（共享 Valkey）；
- CC/封禁/行为判定：**连续**（共享 Valkey，切换前 60 次 + 切换后 50 次仍触发阈值 100）；
- TLS 会话恢复：配置 `tls_session_ticket_key` 后跨节点可恢复（已实测 `Reused`）；未配置回退一次完整握手（性能影响，非登录态）；
- 在途长连接（WebSocket/大文件上传）：**断一次**，靠客户端重连（不做 TCP 连接镜像，与主流硬件 WAF 同边界）。

## 3. 交付检查项（主备高可用）

| # | 检查项 | 方法 | 通过标准 |
|---|---|---|---|
| HA-1 | 节点登记与心跳 | 「节点校验」页 | 两节点 ACTIVE、admin_addr/sync_enabled 已登记 |
| HA-2 | 配置一致性 | 「节点校验」一致性视图 | consistent=true |
| HA-3 | 共享判定态 | A 打 60 次 + B 打 60 次同身份写请求（阈值 100） | 触发一次统一限速（behavior_store=valkey 生效） |
| HA-4 | 端口联动 | 拔主节点桥口一根线 | ≤3s 配对口联动 down，状态页 PROPAGATED_DOWN + 告警；插回后自动恢复 |
| HA-5 | 联动抑制 | 人工快速反复断通同一口 | 超限进 SUPPRESSED + 告警；原样保存配置后复位 |
| HA-6 | VIP 漂移 | 停主节点（断电/停机） | ≤5s VIP 到备节点，「HA 主备」页漂移时间线有记录 |
| HA-7 | 会话保持 | 切换前后业务会话 | 用户无需重新登录；CC 计数跨切换连续 |
| HA-8 | TLS 票据恢复 | `openssl s_client -sess_out A → -sess_in B` | `Reused`（已配 tls_session_ticket_key） |
| HA-9 | 告警通知 | 制造 HA-4/HA-6 故障 | 通知渠道收到「基础设施」类 HA 告警 |
| HA-10 | 恢复收敛 | 主节点恢复 | nopreempt 不抢 VIP；人工回切后一致性视图恢复 true |

## 4. 告警接入（通知渠道）

新增 4 个告警类型（系统告警 → 通知渠道「**基础设施**」类别订阅）：

| 类型 | 等级 | 触发 | 自动恢复 |
|---|---|---|---|
| `HA_VIP_FAULT` 主备VIP异常 | HIGH | keepalived FAULT/未运行、配置已下发但 havipd 未上报、状态文件过期 | 状态正常即恢复 |
| `NETWORK_APPLY_FAILED` 网络配置执行失败 | HIGH | network-status ok=false 或状态文件解析失败 | 执行成功即恢复 |
| `LINK_PAIR_DOWN` 端口联动触发 | MEDIUM | 桥成员口链路故障已联动 down | 恢复 BOTH_UP 即恢复 |
| `LINK_PAIR_SUPPRESSED` 端口联动抑制 | HIGH | 联动频率超限冻结 | 复位（重新保存配置）后恢复 |

- 告警由 api 侧 `hastatus` 清扫器每 30s 读本节点边车状态文件产出，合并/冷却/抖动抑制复用系统告警引擎既有机制；
- **如实边界**：当前仅覆盖 api 容器挂载的本节点边车卷；其他节点的 HA 状态告警待节点级遥测通道（设计文档 M2 边界一致）。

## 5. 已知边界（引用设计文档口径，交付必读）

- keepalived 为系统包依赖，需维护版本兼容矩阵；容器化运行需 NET_ADMIN，生产推荐裸机/虚拟机；
- 在途 TCP 连接切换即断（§2.4），长连接重业务需对客户如实说明；
- 共享 Valkey 是判定态单点（故障时 Fail-open 降级，不中断转发）；
- 端口联动依赖网卡 carrier 语义正确，个别驱动/光模块误报需物理环境复测；
- 上游设备的链路切换策略非本系统可控，交付联调项需与上游厂商确认。
