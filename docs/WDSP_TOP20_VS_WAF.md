# 九章 WDSP Top 20 差异化能力 —— 区别于普通 WAF

> 版本：V1.0（2026-09）
> 依据：阶段8任务书（docs/tasks/STAGE_8_UNIFIED_WEB_API_DYNAMIC_PROTECTION.md）、
> 三微模型框架（docs/API_MICRO_MODELS.md）、AI 自动化渗透防护增强实施文档
> （docs/WDSP_AI_PENTEST_PROTECTION_ENHANCEMENT.md）及各 API 能力域设计文档。

## 定位一句话

普通 WAF 是**单请求规则匹配引擎**：用签名规则逐个请求匹配攻击特征，匹配即阻断。
九章 WDSP 是**统一 Web / API 动态防护系统**：一条流量链、一次解析、一个统一请求
上下文，多个检测器共享分析结果，由统一风险决策输出动作——它保护的不是"URL"，
而是"API 资产 + 调用身份 + 业务行为"。

---

## 一、架构层差异

### 1. 统一 Web / API 流量处理链（一次解析）

同一请求只解析一次（头、Cookie、Query、JSON/XML、GraphQL、响应体），WAF 攻击
检测、API 发现、Schema 学习、敏感数据检测共享同一份解析结果。

**普通 WAF**：只做 Web 攻击检测；要 API 安全需在 WAF 后面再串一套独立设备，流量
被重复解析、检测结论互不知晓。

### 2. 请求 + 响应双向防护

响应侧同样建模：响应 Schema 学习、响应字段提取、敏感数据泄露检测、错误信息
泄露识别。

**普通 WAF**：基本只检请求方向，响应侧最多做简单的银行卡号正则脱敏，不理解响应
结构，无法发现"接口多返回了不该返回的字段"。

### 3. 统一风险决策引擎

所有检测器（攻击检测、Schema 偏离、身份异常、BOLA 信号、行为异常）只产出信号，
最终放行 / 观察 / 限流 / 临时封禁 / 阻断由 `decision.Decide` 统一裁决，支持风险
评分叠加而非单命中即判死。

**普通 WAF**：规则命中即动作，缺乏多信号合成，误报只能加白名单，规则越堆越脆。

### 4. 统一安全事件

同一 Request ID 下的 Web 攻击、Schema 偏离、认证异常、越权信号、敏感数据命中
归并为一个主事件 + 多条检测明细，攻击链可完整还原。

**普通 WAF**：每条命中各记一条日志，事件彼此孤立，无法回答"这是一次协同攻击
还是多次偶然命中"。

---

## 二、API 资产层差异（普通 WAF 完全没有这一层）

### 5. API 自动发现与资产清单

从真实流量自动识别 REST / JSON / XML / SOAP / GraphQL / Webhook 接口，持续维护
API 资产清单、用途分类（主分类、操作动作、业务对象）、敏感度与风险标签。

**普通 WAF**：没有资产概念，只有被保护的"站点/域名"。

### 6. API 路径归一化与模板化

`/user/123/orders/987654` 自动归一为 `/user/{id}/orders/{id}`，数字 / UUID /
hex 段识别为路径参数，支持 API 合并与拆分。所有模型和检测都建立在模板而非
原始 URL 上。

**普通 WAF**：按原始 URL 字面匹配，面对 RESTful 路径参数时规则要么失效要么
被迫写成过宽的正则。

### 7. Shadow / Zombie / Deprecated / Debug API 识别

对比登记资产与实际流量，自动发现未登记的 Shadow API、长期无调用的 Zombie API、
已废弃仍可访问的 Deprecated API 和暴露在外的调试/测试接口。

**普通 WAF**：看不见的资产就不存在，更谈不上发现"不该活着的接口"。

### 8. API 生命周期与安全图谱

API 从发现、上线、变更到下线全生命周期管理；API 调用拓扑、身份—API—对象关系
图谱、攻击路径分析，回答"谁能通过哪条路径碰到什么数据"。

**普通 WAF**：无图、无拓扑，只有按时间排列的日志流。

---

## 三、动态学习层差异（WDSP 的核心壁垒）

### 9. 参数微模型 —— 字段形态基线

以单参数为粒度学习每个字段的类型、长度、字符集、值域、枚举、必填性与字段间
关联关系（条件参数、联动约束），覆盖 PATH / Query / Header / Body 嵌套字段。
纪律：**字段名只是数据**，不对 `username`、`amount` 等具体字段名写死规则，任意
业务零配置即可获得基线。

**普通 WAF**：不理解参数语义，`amount=-1`、`role=admin` 这类业务逻辑攻击对
规则引擎完全透明。

### 10. 请求 / 响应 Schema 动态学习与版本管理

学习产出的候选模型经**人工确认后冻结为正式模型**，支持版本差异对比、重新学习
分支和学习样本污染防护；动态学习绝不自动反向扩大正式模型（学习不等于自动放宽）。

**普通 WAF**：无学习能力；少数产品的"自学习"把观测直接变规则，攻击者投毒即可
驯化模型。

### 11. Schema 偏离检测

基于冻结模型检测：未定义参数、参数类型 / 长度 / 数值 / 枚举异常、JSON/XML 结构
异常、请求体与响应体资源超限——即"正向安全模型"，凡不符合已知正常即为可疑。

**普通 WAF**：纯负向模型（黑名单），只能拦截"已知攻击长相"，对零日 Payload 变异
和业务逻辑滥用无能为力。

---

## 四、身份与授权层差异

### 12. 身份微模型 —— 凭据指纹

从 Cookie / Session / Token / JWT / OAuth / API Key 提取**不可逆身份指纹**
（不落明文），归并出可计数的调用者身份；无凭据记为"匿名"，**绝不以 IP 冒充身份**
（NAT/出口代理会污染一切身份维度结论）。

**普通 WAF**：一切归因于 IP，封 IP 误伤整个出口，也无法区分同一 IP 后的不同
账号。

### 13. 访问微模型 —— 环境与对象双维度

以身份指纹为坐标评估访问：环境维度（IP 跳变、异地、UA 突变、速率突增、时段
异常）+ 对象维度（身份 × 对象标识的访问模式），检出账号接管与异常调用。

**普通 WAF**：只有"这个 IP 请求了多少次"，没有"这个账号的行为正不正常"。

### 14. BOLA / BFLA / 字段级越权辅助检测

对象级越权（改个 ID 看别人的数据）、功能级越权（普通用户调管理接口）、字段级
越权（响应多返回越权字段）的辅助检测，覆盖 OWASP API Security Top 10 的前三位。

**普通 WAF**：越权请求每个字都"合法"，规则引擎原理性无解——这是 API 时代最大的
防护盲区。

### 15. Mass Assignment 检测

检测请求中携带模型定义之外的批量赋值字段（如注册时夹带 `is_admin=true`）。

**普通 WAF**：不掌握接口的合法字段集合，无法判断"多出来的字段"。

---

## 五、行为与数据层差异

### 16. 业务流程偏离与行为基线

对登录、下单、查询等业务流程建立调用序列与速率基线，识别流程绕过、低频慢速
探测、批量抓取和资源滥用（薅羊毛、爬虫、撞库后的数据收割）。

**普通 WAF**：CC 防护只看单 IP 固定阈值，低慢分布式攻击和"每一步都合法但整体
是滥用"的行为完全漏过。

### 17. 敏感数据发现与泄露检测

请求与响应双侧敏感数据识别、数据流分析与跨境流动审计，发现"哪个接口在向外
流出什么级别的数据"。

**普通 WAF**：防的是"进来"，对"出去"的数据基本不设防。

### 18. 多维度精细限流

按身份指纹、Token、租户、API 模板等维度限流（而非仅 IP 阈值），速率基线相对
突增告警（RATE_SPIKE）与绝对上限双轨。

**普通 WAF**：按 IP 一刀切限速，面对代理池与合法大出口同时失效。

---

## 六、对抗与运营层差异

### 19. 面向 AI 自动化渗透的对抗能力

针对 AI Agent 驱动的自动化攻击链——自动侦察、Payload 自动变异、API 枚举、
认证攻击、BOLA/BFLA 探测、低慢攻击——以身份 + 行为 + Schema + 解析一致性 +
风险评分合成识别，而非指望规则追上变异速度。

**普通 WAF**：AI 把"改 Payload 绕过规则"的成本降到接近零，纯签名防御的对抗
天平已经倾斜。

### 20. AI 安全运营打通

与平台 AI 安全运营能力（AI 分析工具、事件研判、报表）原生打通，检测信号直接
成为 AI 研判的输入，形成"检测—研判—处置—模型修订"闭环。

**普通 WAF**：日志导出后人工分析，研判与处置割裂在产品之外。
