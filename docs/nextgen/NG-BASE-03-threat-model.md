# NG-BASE-03 威胁模型、权限与失败策略评审稿（S0）

> 任务来源：docs/WDSP_API_WAF_NEXTGEN_RD_PLAN.md §15.2 NG-BASE-03；输入：NG-BASE-01 基线、NG-BASE-02 契约。
> 状态：v0.1 评审稿（2026-10-03）。§6 待签核项闭环前，依赖它们的实现阶段（S3 授权实断、S4 强流程、S7 身份试点）不得开工。

## 1. 资产清单

| 资产 | 说明 | 失窃/被篡改后果 |
|---|---|---|
| A1 管理面与账户体系 | 控制台、API、会话（Valkey）、RBAC | 全系统策略被接管 |
| A2 策略与关系资产 | WAF/API 策略、对象关系、流程定义、协议资产（Schema/描述符/工具目录）及其**签名快照与版本** | 防护被静默削弱；越权被「合法化」 |
| A3 身份资产 | JWT 信任链配置、机器身份公钥、DPoP/签名密钥、会话密钥 | 伪造可信主体，击穿授权与流程防护 |
| A4 密钥资产 | JIUZHANG_MASTER_KEY、对象 HMAC 密钥、发布签名私钥、授权签发私钥 | 快照/关系/许可被伪造；历史数据被解密 |
| A5 证据与事件数据 | 安全事件、覆盖观测、授权审计、执行结果 | 事故无法定责；证据被删改掩盖攻击 |
| A6 发布链 | 配置快照、内容摘要、能力协商、节点 ACK、升级包与签名 | 恶意配置/镜像下发到全部节点 |
| A7 网关数据面可用性 | CPU/内存/连接/状态键/队列 | 防护面自身被打垮形成盲区或业务中断 |

## 2. 信任边界

| 边界 | 穿越物 | 既有控制 | 本轮新增关注 |
|---|---|---|---|
| B1 客户端 → 网关 | 全部业务流量 | 真实 IP、JWT、WAF、CC、Bot | 协议层放大（GraphQL/gRPC/MCP）；编码混淆；请求走私 |
| B2 网关 → 源站 | 已决策流量 | 统一决策、协议适配执行 | 「已转发事实」记账；响应阶段不可撤回边界 |
| B3 管理面 → 网关（发布链） | 策略/快照/撤销水位 | 不可变快照、内容摘要、Unix Socket 管理端点、节点确认 | 能力协商（旧节点拒绝新策略）；水位单调性 |
| B4 权威来源 → 管理面 | 对象关系、机器公钥、工具目录 | 离线签名导入（规划） | 来源身份验证、重放/乱序/缺口、范围权限 |
| B5 节点 ↔ 节点（多网关） | Valkey 状态、重放记录 | 超时与并发上限 | 状态不可用时不得静默本地降级（强流程/重放） |
| B6 交付物 → 目标机 | 离线包/升级包 | SHA-256、Ed25519 签名、版本门禁 | 包内容审计（无测试代码/文档/私钥） |

## 3. 滥用场景库（按方向 × 威胁类别）

| # | 场景 | 类别 | 受影响契约 | 缓解与门禁 | 验收映射 |
|---|------|------|-----------|-----------|---------|
| T1 | 深层/宽层/批处理 GraphQL 查询耗尽网关 CPU | 放大 | CoverageObservation、limits | AST 节点/深度/alias/batch/变量体积硬上限 + 成本预算 + 全局并发限额 | NG-T-G02/G04 |
| T2 | 多 operation 文档绕过成本核算 | 绕过 | GraphQL 操作选择 | 仅按 operationName 选定执行；未选择/多操作/语法错误分别处理 | NG-T-G01 |
| T3 | gzip/自定义压缩 gRPC 消息膨胀攻击 | 放大 | limits、CoverageObservation | 压缩字节/解压字节/倍率/CPU 四限额；先验证帧声明长度再分配 | NG-T-R02 |
| T4 | 伪造「对象所有者」历史访问升级为阻断资格 | 伪造 | EnforcementEvidence | `HISTORY_INFERRED` 永远 NOT_ELIGIBLE；资格只认 MANUAL_CONFIRMED/AUTHORITY_SYNC | NG-T-A02 |
| T5 | 撤销后借 PreviousValid 回退恢复旧许可 | 降级 | SnapshotWatermark | 水位单调不下降；回退仅落在不越水位的有效快照 | NG-T-A05 |
| T6 | 快照/关系来源重放与乱序注入 | 重放 | 权威导入批次 | 单调序列缺口检测、事件 ID 幂等、缺口标记数据不完整 | NG-T-A06 |
| T7 | 高延迟/断连节点持陈旧授权继续放行 | 分区 | lease/node_applied | 租约上限 + 未 ACK 节点展示 + 过期后按批准策略处理 | NG-T-A07 |
| T8 | 强流程「超时=失败」自动允许重试造成重复扣款 | 绕过 | ExecutionOutcome/流程状态 | 超时 → INDETERMINATE 对账，不自动回滚为可重试；fencing token | NG-T-F04/F05 |
| T9 | 同一幂等键不同参数重试 | 绕过 | 流程操作 ID | 键绑定参数摘要，异参冲突 | NG-T-F03 |
| T10 | MCP 提示词注入「我是管理员」提权 | 伪造 | 身份上下文 | 文本永不改变身份/权限；仅作风险线索 | NG-T-M06 |
| T11 | MCP 工具同名换 Schema 继承旧审批 | 降级 | 工具目录版本 | 策略绑定版本/摘要，变更进待审核 | NG-T-M02 |
| T12 | Token passthrough 至下游工具服务 | 伪造 | MCP 认证 | 受众校验；禁止任意转交 | NG-T-M01 |
| T13 | 覆盖信号（截断/依赖故障）被决策引擎升为 BLOCK | 降级 | CoverageObservation | 独立通道、永不计攻击分（ADR-2） | NG-T-C03 |
| T14 | 旧节点收到新契约策略后「忽略未知字段」假装生效 | 降级 | CapabilityManifest | 写侧能力协商，缺能力发布失败（ADR/CAP_MISSING） | NG-T-C08 |

## 4. 权限评审（拟新增权限键）

| 权限键（候选名，S1 冻结） | 职责 | 授予建议 | 特别约束 |
|---|---|---|---|
| `api_protection.read` | 统一执行覆盖查询 | 安全运营/审计 | 不含敏感明细 |
| `api_protection.validate` | 创建无副作用模拟 | 安全运营 | 模拟产物不触网（断言） |
| `api_authorization.authority_manage` | 权威来源登记/启停 | 安全负责人 | 建议双人复核（阶段 0 定） |
| `api_authorization.authority_import` | 离线批次导入 | 安全运营 | 与来源管理分权；不混用管理员登录凭据做业务推送 |
| `api_flow.recover` | 流程实例人工恢复 | 业务负责人 + 安全负责人 | 必须理由+审计；禁止「一键置成功」；只读角色不得恢复 |
| `mcp_catalog.read / .manage` | MCP 工具目录查询/登记与审核 | 安全运营 / 安全负责人 | 目录变更进待审核，不自动信任 |
| `machine_identity.read / .manage` | 机器身份与公钥登记/撤销 | 安全负责人 | 撤销产生水位，不回滚 |
| `mcp_approval.review`（完整审批子阶段） | 高风险工具调用审批 | 业务负责人 | 禁止只读管理员批准有副作用操作；是否双人复核阶段 0 定 |

通用要求（全部适用）：迁移注册权限种子、后端逐请求校验、前端隐藏+禁用双控、跨应用/越权访问测试（NG-T-C09）、审计含范围与原因。读权限者不得执行任何确认/恢复/审批/发布动作。

## 5. 失败策略评审（RD_PLAN §4.5 矩阵落地）

| 情况 | 默认（本轮批准） | 可选严格策略（按端点单独批准） | 必须可见 |
|---|---|---|---|
| 授权对象未匹配/缺可信主体 | UNKNOWN，继续既有防护 | 特定端点拒绝「准入条件不满足」（非越权语义） | 缺什么证据、范围 |
| 关系快照过期/验签失败 | 不使用该快照，记降级 | 预批准端点 503（协议等价） | 快照版本、原因 |
| 权威同步中断 | 租约内用已验证快照 | 租约到期严格拒绝 | 数据年龄、未 ACK 节点 |
| Valkey 不可用 | 观察型路径按原设计降级 | 强流程/重放**按批准策略拒绝或暂停**，禁止静默切本地内存 | 一致性不可用 |
| 解析/解压/AST 超硬上限 | 停止解析（保网关） | 准入资源上限按冻结响应码拒绝 | LIMIT_EXCEEDED |
| 流式已输出后禁后续违规 | 单独声明能力边界 | 需全量检查的接口发布时拒绝该配置 | 已转发字节不可撤回 |
| 节点不支持新契约 | 该节点发布失败 | —（无「忽略后继续」选项） | 能力缺口 |
| 观测/证据队列满 | 丢低优先级明细并计数 | 关键管理变更持久化失败则拒绝操作 | 丢弃计数 |

评审结论：默认列可直接进入 S1；严格策略列**逐项需要业务端点 owner 书面批准**（影响可用性），批准记录随策略版本归档。

## 7. 与 RD_PLAN §18 风险表的差异说明

本稿把 RD_PLAN §18 的 8 项风险逐条落实到了 §3 场景（T1-T20）与 §5 矩阵，无新增矛盾；唯一收紧：MCP 完整审批子阶段在客户确认前默认 NOT_APPLICABLE（RD_PLAN §11.3 首期边界），不得把「默认拒绝+事件」表述为审批闭环。
