## 3. 隔离与预检

### 3.1 环境契约

1. 每次运行生成唯一 run_id 和 Compose project，容器、网络、卷、数据库均独立；避免固定生产端口和固定共享容器名。
2. 接入测试源站、PostgreSQL、Valkey、日志接收及真实网关/管理服务。按测量范围启用真实 APM 数据面；不能用假 API 回包代替被测服务。
3. 锁定镜像版本/digest；记录 CPU/内存配额、宿主拓扑、存储、网络、TLS、压测器版本与授权配额。
4. 运行器预检目标地址属于该项目网络或登记的专用测试地址，并校验环境唯一标识。仅设置 `ALLOW_TEST=true` 不足以证明隔离。重定向不可逃离允许目标。
5. 数据库重建、容器停止、卷删除和故障注入必须同时验证 project 标签与本次 run_id。禁止全局 prune、停止所有容器或修改共享系统设置。
6. 发现端口占用、目标身份不符、授权配额干扰、版本/配置未生效、时钟异常或压测器资源饱和时停止并标记无效运行。
7. 所需密码通过测试环境注入；命令、报告和采集器不得输出环境变量全集、原始 Authorization 或完整 docker inspect 数据。

### 3.2 源站正确性

正式计时前，对每个请求场景检查状态码、响应内容/长度、上传是否完整读取、流式连接是否按预期结束。上传到不读 body 的 404 路由可能导致误判，必须在预检阶段阻止。

测量包含：固定小 JSON、较大 JSON、表单/上传、合法 Unicode、长连接/流式场景。不同负载分别报告，不将它们的分位数混合成一个无说明的总值。

## 4. 七种模式与变量控制

| Profile ID | WAF | API 动态防护 | 目的 |
|---|---|---|---|
| proxy | 关闭 | 关闭 | 代理基线 |
| waf_observe | DetectionOnly | 关闭 | WAF 检测开销 |
| waf_protect | 拦截 | 关闭 | WAF 防护开销 |
| api_observe | 关闭 | OBSERVE | API 检测开销 |
| api_protect | 关闭 | PROTECT | API 防护开销 |
| combined_observe | DetectionOnly | OBSERVE | 组合观察开销 |
| combined_protect | 拦截 | PROTECT | 组合防护开销 |

同一轮七种模式必须使用相同二进制/镜像、源站、基础规则内容、模型版本、硬件、网络、TLS、日志策略和测试数据，只改变表中明确的开关。切换后等全部目标节点回执并验证有效配置，保存规范化配置差异；出现其他差异则该比较无效。

JWT、响应检测、身份行为、日志采样、APM 等额外开关必须在 run-plan 中写明。JWT 默认不混入七模式的主基线；S3 后增加标明 JWT 模式的配对实验。不能将无 JWT 的旧结果与开启 JWT 的新结果直接归因于代码回归。

规则调优后重跑整个相应比较组，不能只挑某个最优结果。固定随机种子并随机化模式执行顺序，每个性能点至少三次有效重复；报告全部重复、离散程度及异常原因。

## 5. 正常与攻击语料真值

每条样本至少包含 case_id、类别、请求模板、数据生成种子、正常/攻击标签、期望识别模块、各模式期望动作、源站期望、期望事件、授权说明及来源/许可证。

正常语料覆盖：合法 SQL/代码文本提交、搜索符号、中文与 Unicode、JSON/XML、multipart、上传、分页、共享对象/角色切换、合法 JWT、边界大小。攻击语料使用隔离目标覆盖项目声称支持的注入、路径、协议、API schema/行为/响应、JWT 与例外逃逸边界；不把产品未声明支持的检测算作已覆盖。

将“是否产生正确检测证据”和“是否采取正确处置”分开计算：

- 检测误报率：正常样本中错误产生安全检测的数量 / 正常有效样本数。
- 拦截误报率：正常样本中非预期拒绝/限速的数量 / 正常有效样本数。
- 检测漏报率：应被当前声明能力检出的攻击中未检出的数量 / 对应攻击样本数。
- 拦截漏报率：PROTECT 下应拦截的攻击实际未拦截的数量 / 应拦截攻击数。
- OBSERVE 下正确放行攻击不是“拦截漏报”；无适用分母显示 N/A，不输出 0%。

逐样本保存 TP/FP/TN/FN 与请求/事件关联证据；报告不可只保留汇总。必测安全回归用例必须全部满足断言，不能用平均识别率掩盖特定绕过。

## 6. 测量协议

### 6.1 流量与资源

以下时长是本任务的建议默认值，不是已有测量结果：预热至少 60 秒；每个稳定负载点至少测量 5 分钟；每点至少 3 次有效运行。另设短时 smoke，只证明工具可运行，不产生容量结论。

先单独确认压测器和源站容量，再逐级增加 offered RPS，观察完成吞吐、超时、非预期错误、P95/P99 与资源变化。优先支持固定到达率的开放模型；若使用闭环并发，报告并发数、吞吐和协调遗漏限制，不能伪称固定到达率结果。

必须记录：offered/completed RPS、连接复用与新建率、端到端延迟直方图、P50/P95/P99、超时、连接/协议错误、源站错误、预期 403/429、各组件 CPU/RSS/内存、磁盘 IO/增长、网络、队列长度和数据库写入。

安全策略预期返回 403/429 不计入“非预期错误率”，但须单独报告，不能通过把所有 4xx 忽略来隐藏正常流量误拦截。跨运行分位数不能做简单平均冒充整体 P99；保留每次结果，需要合并时合并兼容直方图/原始分布。

### 6.2 事件可见性与完整性

1. 每个应产生日志/事件的请求使用网关可信 request_id，关联 application_id、gateway_node 与 run_id。不要允许用户随意伪造内部关联 ID。
2. 记录请求完成、网关事件产生、持久化和管理查询首次可见时间。跨机时钟同步并记录偏差；页面查询轮询间隔作为测量误差说明。
3. 访问日志、WAF 安全事件、API 主事件分别核对。定义每种数据的产生条件、去重键和是否采样，防止把“未应产生”当作丢失。
4. 输出预期 eligible 数、实际生成数、已持久化唯一数、重复数、待处理数、明确丢弃数与未知差额。恢复后再次核对，不以短时间查询不到直接判断永久丢失。
5. ACK/持久化的边界从当前真实代码确定并写入 run-plan。对已确认持久化的数据要求零永久丢失；崩溃前仅在内存中的数据须单独量化，不能虚构跨崩溃的 exactly-once 保证。
6. 对日志脱敏、响应采样和敏感字段过滤执行验证；证据包保存合成数据和脱敏摘要。

### 6.3 长稳与恢复

- 七模式各完成至少 30 分钟稳定性检查；最终 `combined_protect` 运行 72 小时。负载建议设为实测可持续容量的 60%，记录具体数值与确定方式。
- 按计划注入正常重启、带积压重启、单组件强制终止、Valkey/数据库短暂不可达、有限磁盘空间和队列背压。每次限定作用组件、持续时间、停止条件和恢复操作。
- 检查服务恢复时间、事件追平时间、检查点一致性、重复与丢失、配置版本、内存/磁盘增长趋势以及异常是否可见。
- 不使用一次 30 秒零错误证明长稳；不使用恢复后首页有数据证明积压全部恢复。

## 7. 预登记门槛与结果判定

在运行前生成不可覆盖的 run-plan，至少登记环境、构建、配置、语料哈希、负载、所有时长、重复次数、资源上限、错误率门槛、P99 门槛、事件可见延迟门槛和恢复时限。缺字段时最终验收拒绝启动；smoke 可运行但只能标记 smoke。

建议初始内部回归门槛如下，实施者可根据目标硬件在前测前调整并记录理由；它们是项目验收目标，不是客户 SLA：

| 项目 | 初始内部门槛 |
|---|---|
| 必测安全正确性 | 必测样本全部符合模式对应断言，新增正常流量误拦截为 0 |
| 正常流量非预期错误率 | 稳定目标负载下 ≤ 0.1%；原始失败逐项可查 |
| 同 profile 吞吐回归 | 同一非饱和约束/容量判据下不低于前测的 90% |
| 同 profile P99 回归 | 不超过 `max(前测 P99 × 1.15, 前测 P99 + 2ms)`；抖动超过阈值时重建有效比较组 |
| 已确认持久化事件 | 恢复追平后永久丢失为 0；存储重复不超过契约允许且查询不得重复主事件 |
| 可见延迟与恢复时限 | 在 run-plan 填写目标硬件对应的绝对毫秒/秒值，必须在正式测量前冻结 |
| 资源 | 无 OOM、无未说明重启、队列不无限增长；稳态内存增长与磁盘保留上限在 run-plan 明确 |

前测没有该能力时，先形成新 profile 的基线，不能编造回归百分比。跨 profile 的差异用于描述防护开销，不套用“相同配置回归”门槛。运行后改变门槛必须生成新计划和新运行，保留旧失败，禁止原地修改让结果变绿。

## 9. 必须通过的验收用例

| ID | 操作/条件 | 预期 |
|---|---|---|
| BENCH-01 | 两个不同 run_id 同时创建测试环境 | 资源隔离，清理一个不影响另一个 |
| BENCH-02 | 输入共享/外部目标、错误环境标识、重定向到外部 | 预检失败，不发送压测/攻击流量 |
| BENCH-03 | 上传源站不读 body 或返回意外 404 | 正式计时被阻止 |
| BENCH-04 | 七模式切换，有节点未回执或非预期配置差异 | 该轮无效，不能继续生成可比结论 |
| BENCH-05 | 正常与攻击混合，含预期 403/429 和零分母类别 | 检测/处置指标分开，分母正确，N/A 明确 |
| BENCH-06 | 用已知分布校验分位数、遗漏与汇总 | P95/P99 算法正确，无平均分位数伪汇总 |

BENCH-01～10 包含工具测试和短时真实集成；BENCH-11～12 是真实环境最终验收，不能用单元测试替代。

## 10. 回退与交付边界

运行器中断时只清理本 run_id 的临时资源，保留证据。清理前校验归属；不要在 trap 中广泛删除临时目录或数据库。故障恢复不能顺便调整生产参数。

S2 交付工具、语料、失败用例与前测记录；S5 交付最终安全/性能/长稳/恢复证据及与前测的差异解释。没有目标硬件或足够运行时间时，明确环境阻塞，工具完成与实测完成分别记录。
