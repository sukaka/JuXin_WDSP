# WDSP 四项 P0 开发总纲与大模型执行入口

文档日期：2026-09-06。状态：开发任务书，尚未据此完成开发或验收。

## 1. 目标与使用方式

将[竞品差距分析](../../evidence/wdsp-competitor-gap-analysis-2026-09-06.md)第 7 节的四项 P0 转化为可实施、可复核的交付任务。P0 表示产品工作优先级，不代表漏洞严重等级。

| 编号 | 任务书 | 完成后应获得的结果 |
|---|---|---|
| P0-01 | [版本能力与证据清单](P0-01_CAPABILITY_EVIDENCE.md) | 能回答某个构建实际具备哪些能力、哪些经过验证，以及证据在哪里 |
| P0-02 | [同配置安全与性能基准](P0-02_SECURITY_PERFORMANCE_BENCHMARK.md) | 在可重复、隔离的条件下比较防护模式，报告误报、漏报、延迟、资源和数据完整性 |
| P0-03 | [业务 JWT 信任链与身份标识](P0-03_JWT_TRUST_CHAIN.md) | 业务身份具有可验证的来源，未验证 JWT 不被当作可信授权依据 |
| P0-04 | [最终处置解释与有限范围例外](P0-04_DECISION_SCOPED_EXCEPTIONS.md) | 一次请求的最终处置可追溯，例外仅在声明的对象、规则和有效时间内生效 |

交给开发模型时，提供仓库访问权限、本文件及当前阶段的任务书；要求先读取根目录 AGENTS.md。阶段执行证据和接续信息统一写入 [WORKLOG.md](WORKLOG.md)。不得仅凭阅读本任务书宣称功能已完成。

## 2. 现状与证据边界

本任务书根据 2026-09-06 的当前工作区编写，检查时 HEAD 为 `3c73774`，工作区存在大量未提交改动。因此本次观察不能仅归因于该提交。执行者必须重新检查当前分支、提交、相关文件差异与测试，不得覆盖已有工作。

已存在的能力包括：交付检查模块、WAF 例外 CRUD、从事件创建例外草稿、API 统一决策、身份行为观测、性能回放脚本、安全事件与 APM 的部分关联。四项任务是在这些基础上补齐可信度、约束和验收，不是重建四套系统。

文档中的标记含义：

- **现有**：编写时已在工作区找到；执行前仍须核实。
- **新增约定**：本任务要求实现的接口、字段、目录或行为，不表示代码已经存在。
- **建议默认值**：本任务确定的初始产品参数，调整时须记录原因并同步测试；不是性能测量值或行业标准。
- **待复现**：有代码线索，需用可运行测试确认影响，不能直接当作已证实的线上事故。

## 3. 范围与共同约束

### 3.1 本次包含与不包含

包含四项任务对应的后端、网关、必要管理页面、迁移、权限、审计、OpenAPI、自动化测试与证据文档。任务书中定义的新接口必须实际实现后才能进入正式接口清单。

不扩展到 Bot 挑战、全球 DDoS 网络、千 Agent 容量、AF_XDP、完整 OIDC 登录、业务授权引擎或 AI 自动处置。APM 与 Agent 必须出现在能力清单和兼容性检查中；本轮不以新建这些模块替代四项 P0。

### 3.2 不得破坏的行为

1. 保持 AGENTS.md 与真实网关一致的请求顺序。人工临时封禁先于白名单；白名单与 L7 allow 不绕过 WAF 和 API 动态防护。
2. 身份行为观测继续 fail-open；新 JWT PROTECT 的强制校验不得依赖该观测模块成功与否。
3. API 决策结果与整条请求的最终处置分开保存；API ALLOW 不能覆盖后续 Coraza BLOCK。
4. 认证、权限、CSRF、输入校验和日志脱敏不得为测试让步。用户提交的配置必须经过后端校验。
5. 复用既有配置编译、审核、发布、节点回执和回退链路。草稿保存不等于线上生效。
6. 依赖与镜像锁定版本；依赖许可证遵循项目约束。不得复制竞品代码、接口、数据库结构或页面。
7. 不把真实 Token、请求敏感正文、私钥、密码或完整业务身份声明写入 Git、事件、报告或测试输出。
8. 新行为须有单元测试；新接口须有接口测试；关键操作须有真实网关集成和 E2E。测试依赖缺失或用例 SKIP 不等于通过。

### 3.3 版本、发布与工作区

以执行时实际版本为准，不使用 AGENTS.md 中的历史示例倒退版本。遵循当前用户授权和仓库发布规则；文档交付本身不触发应用版本升级。不能将所有工作区改动统一 `git add .`，不能将他人未完成工作混入当前任务。发布时记录实际构建提交、镜像 digest 与配置版本。

## 4. 执行顺序与阶段门槛

一次只完成一个阶段或明确模块。下面的“通过”必须对应具体文件、命令、结果和证据。

| 阶段 | 工作 | 进入下一阶段的条件 |
|---|---|---|
| S0 | 核实现状；冻结四份任务书共享字段；建立 WORKLOG | 列出已有实现、真实差距、改动文件和验收 ID；记录工作区基线 |
| S1 | P0-01：证据格式、校验器、初始能力清单 | 自动识别缺证据、错误构建绑定和伪通过；清单可生成 |
| S2 | P0-02：隔离测试工具与改动前基线 | 正常/攻击真值可核验；模式和版本一致；保留原始数据。此时不是最终性能验收 |
| S3 | P0-03：JWT 完整链路 | 单元、接口、真实网关与页面关键流程均通过；故障策略和身份隔离经过验证 |
| S4 | P0-04：最终处置与受限例外 | 真实 Coraza / API / 源站归因、精确条件、到期和发布回退全部通过 |
| S5 | P0-02：最终复测、长稳与重启恢复 | 相同环境配置复测；预登记门槛满足；缺失环境不得改写为通过 |
| S6 | P0-01：冻结最终能力与发布证据 | 最终构建与证据一致；所有强制验收项可定位；限制与未完成项如实保留 |

如果 S2 的专用环境暂不可用，可以完成测试工具并标为 `BLOCKED_ENV`，继续准备不依赖测量结果的代码；不得宣布 S2/S5 通过。S5 未通过时，四项 P0 总状态不能为完成。

`BLOCKED_ENV` 是便于阅读的环境阻塞标记；机器验收记录统一保存 `status=BLOCKED`、`reason=ENVIRONMENT_UNAVAILABLE`，不额外扩展状态枚举。

### 4.1 共享契约

| 对象 | 所有任务一致的规则 |
|---|---|
| 构建标识 | 使用 P0-01 的 build identity；dirty 工作树与正式发布证据分开 |
| 配置标识 | 记录具体应用、发布批次、节点确认的有效配置版本，不能拿最新草稿版本填充 |
| 请求关联 | 延用现有 request_id / application_id / gateway_node；核实唯一性与可信来源，不信任外部同名请求头 |
| 身份 | P0-03 的 verification_status 与 verified_principal_id 独立于现有 identity_type、identity_key |
| 最终处置 | P0-04 的 final_decision 独立于 API 的 final_action；无法确认时明确未知或待关联 |
| 例外命中 | 带 exception_id、不可变版本、条件摘要、有效时间及执行节点，不记录敏感匹配值 |
| 验收记录 | 使用任务书中的测试 ID，保存 PASS / FAIL / SKIP / BLOCKED / NOT_RUN，附执行条件与证据哈希 |

新增契约先写入代码类型、迁移和 API 文档，再接入调用方。不得用自由文本猜测枚举或让前后端分别实现不一致的默认值。

## 5. 测试与证据纪律

以下是仓库已有的检查入口，按当前改动选择运行，并在实施前确认依赖。仅改文档时不要求运行应用测试。

```sh
(cd gateway/dynamic_security && go test ./decision ./detectors ./pipeline -count=1)
(cd gateway/modules/jiuzhang_guard && go test -race ./... -count=1)
(cd server && go test ./internal/exceptions ./internal/gatewayconfig ./internal/guardconfig ./internal/apiruntime -count=1)
(cd web && npm run typecheck)
(cd web && npm run lint)
(cd web && npm test)
(cd web && npm run build)
```

接口测试必须使用独立数据库和 Valkey。现有 `server/tests/helper_test.go` 会重建 `jiuzhang_waf_test`，使用 Valkey DB 15，并可能因环境缺失跳过测试。执行者应先读取它；不得对生产或共享数据环境执行。用 `go test -json` 汇总强制用例的实际运行状态，不能只检查退出码。

真实网关集成测试须使用锁定的 Caddy、Coraza、CRS 及应用构建；验证中间件实际顺序。单元测试通过不能替代 Coraza 控制指令、流式响应、到期时钟、真实配置发布和节点回执的验收。

每阶段交付说明须包含：修改目的、文件清单、测试 ID 与结果、原始证据位置、已知限制、迁移/回退步骤、下一阶段依赖。不得把计划执行的命令记为已执行。
