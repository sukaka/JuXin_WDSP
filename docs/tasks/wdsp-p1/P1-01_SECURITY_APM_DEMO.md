# P1-01 安全与 APM 标准客户演示开发任务书

日期：2026-09-06。状态：待实施。优先级：P1。入口：[总纲](README.md)。

## 1. 要解决的问题与完成定义

现有控制台已经能够从安全事件按 Request ID 跳转 APM，但入口本身不能证明客户能完成一次真实调查。本任务交付可重复部署的演示环境和经过测试的调查流程：安全事件 → 关联请求 → Trace → 服务调用 → 慢 SQL / 异常 → 返回事件判断处置。

完成时必须同时具备：真实业务和数据库产生的数据、上下文一致的页面跳转、缺数据与权限的准确反馈、可重复运行的场景、原始证据和用户任务耗时记录。演示视频是辅助材料，不替代运行证据。

本任务不建设新的 APM 平台，不把无探针网关延迟描述为代码级诊断，不增加生产环境故障注入入口，不承诺全部语言探针覆盖。

## 3. 标准演示环境

### 3.1 组成与隔离

**新增约定**：在 `test/security-apm-demo/` 放置独立演示夹具、部署编排、合成业务、数据种子、场景驱动、断言和操作手册；该目录当前不作为已有实现。复用现有网关、管理服务、PostgreSQL、Valkey、Collector 与 ClickHouse 配置，禁止复制一套不随产品升级的管理面。

最小业务由自建 HTTP 服务 A → 服务 B → 独立测试数据库构成；至少一种实际支持的语言通过锁定版本的 OTel SDK/探针产生真实服务 Span、DB Span 和异常。选择语言与采集方式时给出依赖、许可证和实际映射证据，不要求为了演示强行新增所有语言。

场景开关只在该测试业务中存在，默认关闭；不进入产品镜像或业务客户安装包。正常、慢查询和异常使用可控测试数据与有界操作，例如测试库中预先定义的延迟操作；不能接受任意 SQL、命令或外部 URL。管理凭据由运行时环境提供，不写入脚本或录屏。

每次运行具备独立 run_id、Compose project、数据卷、测试应用和请求集合；清理只删除本次创建的资源。启动失败不修改客户站点配置；不得执行无范围的数据库清空或全局容器清理。

### 3.2 必须出现的真实场景

| 场景 | 真实输入与状态 | 页面应展示的事实 |
|---|---|---|
| 正常调用 | 浏览器调用服务 A，经 B 查询数据库 | 实际 Trace 与调用层次；无样本时不能补一条演示 Trace |
| 命中但观察 | 明确会触发测试规则的请求，在 OBSERVE 模式下到达测试业务 | 同一次请求的安全事件和上游 Trace 可相互定位；命中不等于阻断 |
| 网关阻断 | 对同一夹具启用已发布的阻断策略 | 最终执行模块、请求状态与未到达源站证据；无应用 Span 是预期结果 |
| 慢 SQL | 合成业务执行可控延迟数据库操作 | 对应 Trace 内真实 DB Span 与 SQL 指纹，时间量纲一致 |
| 应用异常 | 合成业务按场景产生已知异常 | 对应异常 Span、脱敏异常摘要和实际响应；不能把 WAF 403 当应用异常 |
| 同时但无关 | 独立请求产生攻击告警，同时另一请求产生慢 SQL | 可按 ID 区分，界面仅说明时间关联，不自动断言攻击导致性能下降 |
| 仅网关观测 | 关闭应用采集，保留网关访问和指标 | 仅展示入口延迟、TTFB 等实际可得数据；SQL、代码级耗时不可用 |
| 数据面异常 | 停采样、停止 Collector、阻断 CH 查询分别执行 | 分别展示有证据的原因；不知道原因时明确未知 |

保持正常与攻击请求具有不同的内部 Request ID。若应用未运行到数据库步骤，不允许为了展示 SQL 关联而连接别的请求。

## 4. 关联与查询契约

### 4.1 可信关联

沿用既有内部 Request ID / Trace ID 生成和传播链，先验证网关到业务、跨服务、Collector 到存储的映射。外部传入同名 Header 不得覆盖内部关联标识。Trace Context 是分布式追踪协议，不赋予业务身份或访问授权；遵循 [W3C Trace Context](https://www.w3.org/TR/trace-context/) 的格式与隐私边界，映射规则以产品实际可信边界为准。

关联键至少包含 application_id、内部 request_id、gateway_node 和有界事件时间窗；Trace ID 可作精确索引，但查询仍须经过授权。应用下钻过滤与权限校验是两件事，不能把 URL 上有 application_id 当作已授权。

若现有权限仅提供全局 APM 读取能力，应明确其全局范围，复用真实授权模型，不宣称已经具有应用级 RBAC。若系统已有应用范围权限，必须在服务端过滤；同一 Trace 跨越无权查看的服务时只返回授权部分并标记 PARTIAL，不能因有一个入口应用权限而暴露整个调用链。

一对多时返回候选及各自时间、服务和匹配依据；不能任取第一条。跨时间窗、跨应用、碰撞 ID、过期保留期不确定时，不自动建立强关联。一次请求尚未入库时允许有界等待，不能永久轮询。

### 4.2 现有接口的增量

**新增约定**：优先扩展下列已有 GET 接口，不另建一个复制全部 APM 数据的“演示 API”。新参数、字段同步到类型、查询实现、API 文档与测试。

| 已有接口 | 本任务增量 | 权限与限制 |
|---|---|---|
| `/api/v1/apm/trace-search` | 在现有 request_id / 时间检索基础上核实并补齐 application_id 约束，返回 availability 与 correlation | `apm.traces.read`；窗口保留最多 24 小时、分页最多 100 条 |
| `/api/v1/apm/traces/{trace_id}` | 详情校验应用/时间上下文；返回关联和 Span 完整性 | 同上；不泄露未授权安全事件正文 |
| `/api/v1/apm/sql` | 现有聚合查询保留；需要 Trace 级定位时补精确过滤或从 Span 内定位指纹 | `apm.sql.read`；不将全时间窗 SQL 排名标为“该请求慢 SQL” |
| `/api/v1/apm/exceptions` | 补足 Trace 级定位及数据质量；无精确字段时明确仅为相关候选 | `apm.traces.read`；限制返回堆栈和文本长度 |
| `/api/v1/apm/services`、`/api/v1/apm/overview` | 明确网关观测、已接入探针、实际 Span 可用性三种事实 | 保留各接口原权限；访问日志关闭不影响已有应用级数据 |

新增过滤不可静默忽略；不支持的组合返回明确校验错误，避免用户以为范围已缩小。前端旧字段兼容保留，新的状态控制提示；所有错误对客户端使用安全摘要，不回显 DSN、查询语句或连接凭据。

### 4.3 数据质量字段

**新增约定**：在现有响应 data 中添加 `availability`，不用 `data_source=agentless` 承载所有健康状态。初期可由现有配置、查询结果、健康缓存和已接收样本计算，不要求建新表；若缺少水位持久化，新增迁移并说明数据来源和保留期。

| 字段 | 取值或类型 | 判定要求 |
|---|---|---|
| `query_state` | READY / EMPTY / PARTIAL / UNAVAILABLE | READY 有实际可用数据；EMPTY 是成功查询的零结果；不能把异常改成 EMPTY |
| `reason_codes` | 字符串数组 | 使用下表冻结枚举；只填有依据的原因，允许多个数据源问题 |
| `observed_sources` | GATEWAY / OTEL 的数组 | 从本次真实查询结果判定，Agent 心跳不能替代实际 Span |
| `last_collected_at` | RFC3339 或 null | 最近实际采集时间；未知不能用 now 填充 |
| `last_ingested_at` | RFC3339 或 null | 最近确认入库时间，注明时钟差容忍；不能由空查询推断 |
| `estimated_lag_ms` | 非负数或 null | 仅有可比较水位时计算；明确是估计而非请求级精确延迟 |
| `partial` | 布尔值 | 丢 Span、授权过滤、单一数据源失败均可能导致部分结果 |

原因枚举：`STORAGE_NOT_CONFIGURED`、`STORAGE_UNAVAILABLE`、`ACCESS_LOG_DISABLED`、`NO_INSTRUMENTATION_CONFIRMED`、`NOT_SAMPLED_CONFIRMED`、`INGESTION_DELAY_CONFIRMED`、`OUTSIDE_RETENTION`、`NO_MATCH`、`UNKNOWN`。其中未接探针与未采样需要注册/配置或采样决策等证据；单凭“没有查到 Span”只能返回 NO_MATCH 或 UNKNOWN。

`correlation` 独立于数据源健康，字段为 `state`、`match_basis`、`candidate_count`、`reason`；state 为 `MATCHED`、`AMBIGUOUS`、`PENDING`、`NOT_FOUND`、`NOT_EXPECTED`、`UNKNOWN`。NOT_EXPECTED 仅用于已证实网关终止且未调用源站的请求，来自 P0 最终处置及源站调用事实，不能由 HTTP 403 推导。

兼容策略：保留现有成功响应 envelope；CH 未配置或降级可保持 HTTP 200，但必须通过 availability 显示 UNAVAILABLE/PARTIAL，监控和验收不能据此算查询健康。现有 APM 总开关关闭继续 503，无权限继续 403；无权限响应不附带存储、探针或事件是否存在的信息。新增字段先部署后端，再部署前端；旧服务端缺少字段时前端显示“状态信息不足”，不编造原因。

## 5. 用户流程与文案要求

1. 事件详情的“查看关联调用链”保留 application_id、事件前后各 5 分钟的时间窗及 request_id；±5 分钟是建议默认值，允许用户手动扩展到接口上限。返回链接仅允许站内已知路由，不接受任意外部跳转。
2. 初次查询明确加载；有证据表明数据尚在入库时显示采集和入库时间。建议最多自动等待 30 秒，之后提供手动刷新与排障入口；页面卸载取消请求。
3. 无应用采集时解释“目前仅有网关观测数据”，提供既有接入指南；不能让用户误以为安装流量 Agent 就会生成代码 Trace。
4. 存储不可用时显示“调用链存储暂不可用”，保留网关事件上下文和重试；不显示“业务健康”“无异常”的零值结论。
5. Trace 中展示关联强度、节点、服务、时间与数据完整性。跨页 SQL/异常使用相同过滤条件；没有精确关系时显示“同时间窗候选”，不能写成已定位根因。
6. 无权限时隐藏敏感入口并由接口兜底。仅有 Trace 权限而无 SQL 权限时，SQL 字段与下钻按权限裁剪，不能通过 Span attributes 绕过独立 SQL 权限读取完整内容。
7. SQL 参数、Authorization、Cookie、个人身份字段和异常消息中的敏感值统一脱敏；堆栈纯文本、有长度上限。空态和错误态支持键盘操作，不能出现无限 Spinner。

诊断会话属于可选演示环节；如演示它，必须走已有权限、预估、确认、短时有效期、停止和操作审计，不自动提高生产采样率。单纯阅读调查页不应产生诊断副作用。

## 7. 验收矩阵

全部为强制验收；多场景行中的各个子场景都要保留结果。

| ID | 类型 | 输入或动作 | 必须满足的断言 |
|---|---|---|---|
| APMD-001 | 真实集成 | 干净环境启动，运行正常跨服务调用 | 实际业务、DB 和 OTel 数据接线；构建/镜像/配置可定位 |
| APMD-002 | 网关 + E2E | OBSERVE 命中后从事件跳转 | request_id、应用和时间一致，找到实际上游 Trace |
| APMD-003 | 网关 + E2E | PROTECT 阻断，源站记录调用数 | 源站未收到请求；无应用 Trace 为 NOT_EXPECTED，展示真实执行模块 |
| APMD-004 | 真实集成 | 单次可控慢 SQL | 目标 Trace 的 DB Span 与 SQL 指纹关联，不能取其他请求替代 |
| APMD-005 | 真实集成 | 单次可控异常 | 异常和目标 Trace 对应；敏感异常值已脱敏 |
| APMD-006 | E2E | 不相关攻击与慢 SQL 同时发生 | 可区分请求；不自动生成因果断言 |
| APMD-007 | 真实集成 | 无应用采集，保留网关数据 | 网关数据可用，代码/SQL 不伪造，不将流量 Agent 心跳当探针证据 |
| APMD-008 | 接口 + E2E | 显式不采样与未知缺样本分别执行 | 有采样证据才返回 NOT_SAMPLED_CONFIRMED；其余明确未知/无匹配 |
| APMD-009 | 故障 + E2E | CH 未配置、CH 不可达分别查询 | 原因可区分；无敏感连接信息，存储失败不显示健康空图 |
| APMD-010 | 故障 + E2E | Collector 延迟并恢复 | 显示真实水位或未知；有界等待，恢复后能定位，不无限轮询 |
| APMD-011 | 权限 | 无 APM 权限、无 SQL 权限、直接访问 API | 403/字段裁剪符合现有模型；不能通过 Span 绕过 SQL 权限 |
| APMD-012 | 安全 | 伪造 ID、跨应用、碰撞、多候选、外部返回 URL | 不能串联错误请求或越权读取；多候选不任选；无开放重定向 |
| APMD-013 | 接口 | 超长 ID、非法时间、超窗、分页和过滤组合 | 后端校验及查询上限有效；不静默丢过滤条件 |
| APMD-014 | 安全 | Header/SQL/堆栈含敏感值与 HTML | 数据面、接口、UI、导出/证据均无原始敏感值或脚本执行 |
| APMD-015 | 兼容 | APM 开关关闭、旧后端、访问日志关闭 | 原开关语义保留；缺字段显示状态不足；关闭访问日志不影响既有应用探针数据，网关指标缺失如实说明 |
| APMD-016 | UX | 刷新深链、返回、键盘、窄屏、失败后重试 | 上下文保留，可操作，无空白页、无限 Spinner 或颜色唯一提示 |
| APMD-017 | 用户验证 | 按冻结任务脚本完成调查 | 记录原始耗时、是否成功、误判与求助；不编造效率提升比例 |
| APMD-018 | 运维 | 关闭演示、回退前后端、清理本次资源 | 原业务和数据不受影响；兼容字段不破坏旧页面；清理范围正确 |

APMD-017 建议邀请至少 3 名未参与实现的使用者执行同一脚本，分别记录首次事件定位、Trace 定位和 SQL/异常判断的起止时刻。成功判据是正确指出请求、处置、证据和未知部分；不能只统计点击完成。样本少时报告原始值和范围，不做统计显著性或客户 ROI 承诺。人员条件不具备时如实 BLOCKED，不能以开发者熟练操作替代首次使用证据。

## 8. 发布、回退与证据

先部署兼容后端字段，再部署前端；APM 总开关继续控制功能。演示环境的采样和日志配置独立于产品默认值。回退前端无需删数据；新增状态持久化采用增量迁移，回退应用时保留表/列，确认无数据依赖后再另行处理。
