# P1-02：Bot 挑战及多信号策略开发任务书

日期：2026-09-06。状态：待开发与验收。入口：[P1 总纲](README.md)；接续：[WORKLOG.md](WORKLOG.md)。

## 1. 目标与完成定义

在现有身份行为、风险策略和 CC 之上，补齐应用级 Bot 策略、浏览器挑战、有效期内通行、运营解释与回退。策略保存后必须经配置发布和节点确认生效；挑战通过后仍执行业务认证、API 动态防护和 WAF。

P1 交付的是第一方 JavaScript 挑战和多信号决策。JavaScript 执行与有限计算只能增加自动化成本，不能证明真人，也不能识别所有可执行 JS 的自动化浏览器。页面与报告须分别展示普通 HTTP 自动化、可执行 JS 的自动化和正常用户的实测结果。

完成标准：本任务所有 BOT 验收项通过，有正常浏览器、移动端、合法自动化、攻击自动化、双节点和故障场景的原始证据。缺少真实环境时保留 BLOCKED；不能用“挑战页面能显示”代替完整交付。

## 3. 范围与防护链路

### 3.1 本期范围

- 应用级 `OFF / OBSERVE / PROTECT`，默认 OFF；有限路径选择器、信号解释、版本并发控制。
- 第一方、无外部服务依赖的 JavaScript 挑战；短期 nonce、一次消费、签名 clearance、密钥轮换和双节点验证。
- 挑战仅覆盖显式配置路径上的 HTTPS、GET、浏览器文档导航。HEAD、POST、JSON API、文件上传、WebSocket、gRPC、流式请求不返回 HTML 挑战。
- 不符合挑战条件的请求默认仅观测，记录 `INELIGIBLE`。限速继续由真实 CC 计数执行；不能因 UA 或风险分数高就伪称触发了频率阈值。
- 支持关闭、OBSERVE 降级和回退，并留下操作者、原因与节点生效证据。

不包含第三方 CAPTCHA、云端信誉服务、设备唯一标识、Canvas/字体等高侵入指纹，也不自动重放表单或提供全站通行。新增网络调用仅限业务浏览器与当前站点、现有内部状态存储之间的必要交互。

### 3.2 新增步骤与内部端点边界

**新增约定**：Bot 业务判定放在现有 CC 之后、API 动态防护之前，其余步骤保持相对顺序。人工封禁、保护地址、L7 拒绝、自动封禁、风险引擎和配额/CC 的既有拒绝优先；有效 clearance 不绕过这些步骤。IP 白名单或 L7 allow 不隐式跳过 Bot；Bot 适用范围独立、显式配置。

**拟新增保留端点**：`POST /_wdsp/bot/v1/verify`。它由同一应用的网关在 Bot 步骤处理，永不反向代理；只验证网关签发的挑战，不能接收任意业务 URL、目标主机或执行代码。启用前检查路径和 Cookie 名冲突，有冲突拒绝发布，要求用户调整自身路径或在 S0 更换整个保留命名空间。

内部端点仍经过前面的地址、封禁、L7、风险、配额与 CC 检查。不得为了让挑战通过而自动加入全局白名单。管理员将这些路径配置为拒绝时，应在配置预检与 UI 给出冲突，不能发布后让用户陷入循环。

内部验证在此步骤终止，因此不进入后面的业务 API 管线或 Coraza。这个边界必须显式实现为固定协议的本地控制端点：限制方法、Host、正文类型、8 KiB 正文上限、读取超时、会话、nonce、来源和尝试频率；不能复用“跳过 WAF”标志放行任意前缀请求。未知子路径返回本地 404，错误方法返回 405，均不调用源站。业务请求通过挑战后继续经过 API、请求大小/协议检查和 Coraza。

保留路径只在应用启用或明确保留 Bot 路由时注册。首次 OFF 且从未启用的应用不抢占业务路径；从已启用状态关闭时保留本地 404 墓碑路由，直到运维明确解除保留，防止旧挑战提交到业务源站。此保留状态属于版本化配置，不能仅放在节点内存。

更新 AGENTS.md 的请求顺序说明、架构设计和中间件集成测试后才能验收。必须用有效 clearance + SQLi 等真实请求验证后续 WAF 仍然执行。

## 4. 策略、数据和管理接口

以下是**新增约定**，目前不能假设表、字段或路由已经存在。S0 对照既有迁移、权限种子、OpenAPI 与发布契约确定实际落点。

### 4.1 应用策略契约

拟新增 `GET/PUT /api/v1/applications/{application_id}/bot-policy`，复用管理认证、CSRF 和响应封装；新增最小权限 `bot_policy.read/edit` 并做角色迁移。发布继续走现有发布流程，不能用 GET/PUT 直接声称节点已生效。

| 字段 | 契约 |
|---|---|
| schema_version、id、application_id、version | 版本化结构；应用由授权上下文和持久化关联校验，不信任请求体覆盖 |
| mode | OFF / OBSERVE / PROTECT；未知值拒绝 |
| selectors | 方法固定 GET，路径精确或规范化前缀、HTML 导航条件；明确大小写、编码和前缀分段规则；禁止任意正则和默认全站通配 |
| signal_rules | 稳定规则 ID、信号组、窗口、权重、阈值及最少独立信号组数；所有数值有上下界 |
| challenge | 类型 JS、nonce_ttl_seconds、clearance_ttl_seconds、difficulty、最大尝试数；参数上下界见下一节 |
| key_ref、policy_epoch | 仅引用预置内部签名密钥及撤销代次；不得在普通配置、API 或审计返回私密材料 |
| route_reservation | 保留命名空间及生命周期；用于启用、关闭与路由冲突预检 |
| status | 草稿版本、发布批次、节点有效版本/ACK、依赖健康分别返回；不能混成一个 enabled |

PUT 为完整替换，带 `expected_version` 防丢更新；冲突 409，格式/范围非法 400，不存在 404，无权限 403。复用当前应用权限边界；如果目前只有全局权限，必须如实声明，不得声称已具备应用级 RBAC。所有读写和发布同时校验已有的数据范围。

持久化至少包括策略版本、应用绑定、路由保留与审计记录；nonce/短期会话放入现有共享 Valkey 的独立命名空间，不写业务数据库明文 Token。回退生成新的配置版本，不修改历史版本内容。

### 4.2 多信号判定

信号分组至少区分请求行为、访问序列与客户端声明。UA、Accept、轻量 TLS 特征属于可伪造声明，不能互相冒充多个独立强信号。相同底层计数派生的两个指标不能重复计权。已有 VERIFIED 身份可用作分桶上下文，不直接判定为真人；未验证身份只作低信任观测。

默认至少两个独立信号组同时满足才可提出挑战，且必须有一个来自实际行为观测。S0 将选定信号、窗口、计权和阈值冻结成可解释表，并复用已存在计数；不得填写凭空产生的“AI 风险分”。建议模板先 OBSERVE，采集基线后由操作者明确启用 PROTECT。

输出 `ELIGIBLE / INELIGIBLE`、原因、各组原始计数与窗口、提出的动作、实际动作、策略版本。观测缺失或状态读取失败用 UNKNOWN/UNAVAILABLE；不得把“未采集到”当作零风险或高风险。

## 5. 浏览器挑战与通行安全契约

### 5.1 流程

1. 符合条件的 GET 达到挑战阈值时，网关生成随机会话和挑战 ID，写共享状态，返回 403 挑战 HTML；最终动作记录 CHALLENGE、响应来源 GATEWAY、未访问源站。
2. 浏览器在当前 URL 执行受限的本地 JS，完成 nonce 绑定的计算后，同源 POST 到固定 verify 端点。不得要求用户提供业务账号、密码、短信或任何第三方凭据。
3. 网关原子校验并消费挑战，成功返回 204、设置短期 clearance Cookie；失败返回结构化 400/403/409/429/503，不能设置 clearance。
4. 浏览器成功后只刷新当前 GET URL；不从响应读取任意跳转地址，不存储或提交原 URL 的敏感 query，不重放 POST。最多自动刷新一次，仍被挑战则显示可恢复原因，避免无限循环。
5. 下一次业务请求验证 clearance 及策略代次，在 Bot 步骤通过后继续完整后续防护。不要将通行 Cookie 透传源站或加入访问日志。

### 5.2 计算、会话与 nonce

建议采用标准 SHA-256 的有限工作量题：服务端随机 challenge_id 与随机 nonce 共同参与哈希，浏览器寻找一个有界长度 solution，使摘要满足服务端签发的 difficulty。难度由服务端状态决定，不接受客户端降难度；字段采用固定编码及无歧义长度前缀。禁止自创加密算法。

这是 JavaScript/计算能力检测，自动化浏览器可以求解。验收必须包含能成功求解的自动化样本，不得把其删去后声称真人识别率。

建议默认 difficulty=14 bit、上限 18 bit，nonce TTL=90 秒、clearance TTL=15 分钟、单题最多 3 次验证尝试；参数变化要补资源测试。这些是待测产品初值，不是性能保证。浏览器计算须可中止、定期让出主线程，单次计算预算建议不超过 2 秒；超时给出说明与手动重试，不无限加难度。所有服务端状态有容量和速率上限。

会话和 nonce 均使用密码学安全随机数，至少 128 bit；Cookie 会话 ID 建议 256 bit。服务端只存需要的摘要、题目参数、应用/策略代次、过期和消费状态。验证采用原子比较与消费，绑定浏览器会话、应用、Host、策略代次，跨节点或并发提交至多一次成功；不能先查再删。

### 5.3 Cookie、签名与来源校验

- 使用独立的 `__Host-wdsp-bot-session` 与 `__Host-wdsp-bot-clearance`，Secure、HttpOnly、SameSite=Lax、Path=/，无 Domain；只在 HTTPS 启用。与管理登录会话完全隔离。
- clearance 是有期限的 bearer 通行证明，仅针对 Bot。载荷包含有版本的用途标识、应用、Host、policy_epoch、会话摘要、签发/到期、key_id；用标准库 HMAC-SHA-256 等审查通过的方案签名，严格算法固定、长度校验、恒定时间比较。签名密钥不得与 JWT、CSRF、管理会话或 Agent CA 共用。
- key_id 仅选择本地允许密钥，不能拼接文件路径或 URL。多节点先完成密钥准备再发布策略；旧验签密钥保留时间不超过允许的通行窗口，紧急撤销通过新 policy_epoch 生效。
- IP 可用于速率计数和异常辅助，不能单独作为通行绑定；覆盖移动网络换 IP 与共享 NAT。Cookie 被盗仍存在会话重用风险，不能声称签名消除了这一风险；短 TTL、应用绑定、代次撤销及后续 WAF 共同限制影响。
- verify 严格同源 Origin 校验，不开放跨域，校验 Host 与会话绑定；结合一次性 nonce 及 Fetch Metadata，不能只依赖可伪造的 UA/Header。缺少 Origin 的请求默认拒绝，浏览器兼容问题先实测再写显式例外。
- HTML 使用 CSP nonce、限制脚本/连接到必要的第一方来源、禁止被嵌入；Cache-Control: no-store，不经 CDN 共享缓存。所有提示和被展示的输入按文本转义，不使用 eval。

服务端对同一会话、真实客户端 IP 和应用分别限制签发/验证速率及在途状态总数，避免共享 NAT 被一个简单 IP 阈值整体误伤。限制值与状态容量在 B0 冻结，并在达到上限时明确返回 429 或 503，不允许无限内存增长。

### 5.4 故障与撤销

OFF 不初始化挑战依赖；OBSERVE 记录依赖故障并继续既有链路；PROTECT 中需要挑战或验通行的请求，若共享状态或所需密钥不可用，返回明确 503、Retry-After 和运维告警，不静默签发或接受无法验证的通行。该策略仅适用于新 Bot 步骤，不改变原风险引擎的失败放行契约。

运维可将策略降为 OBSERVE，必须经授权、审计和发布。节点部分成功时显示实际版本；未收到目标版本的节点不能计为保护成功。避免发布时新 key 尚未安装导致全站挑战故障。

## 6. 事件、运营与 UI / UX

复用 [P0-04](../wdsp-p0/P0-04_DECISION_SCOPED_EXCEPTIONS.md) final_decision，新增 CHALLENGE 动作与 Bot executor 的版本化支持。挑战完成事件不是原请求的业务成功事件；原请求返回挑战页后已经结束，刷新后的请求拥有新的 Request ID，通过脱敏 flow_id 关联。

记录 offered、verify_success、verify_rejected、expired、state_unavailable、clearance_accepted，附策略有效版本、节点、信号理由和脱敏 flow_id；不写 nonce、solution、通行 Cookie、会话 Cookie 和签名材料。挑战端点内部流量单独统计，不能算成新增业务攻击或正常业务吞吐。

页面至少提供应用范围、模式、路径预览、信号说明、草稿/已发布/节点版本、依赖故障、近期误挑战反馈和回退入口。不能用“已开启”掩盖仅保存草稿；删除选择器、全站扩展和 PROTECT 变更提供具体影响预览。

终端用户页面有清楚的等待状态、JS 不可用、超时、Cookie 不可用、服务故障与手动重试；支持键盘和读屏，不能只有旋转动画。合法 API/SDK 收到机器可读结果，不能被 HTML 页面破坏协议。

评估分别报告：挑战触发率、每个 flow 的完成率、正常用户误挑战率、正常用户最终业务失败率、各类自动化通行率、挑战增加的延迟、CPU 与状态存储开销。给出分子分母、样本构成与统计窗口，不用 HTTP 请求重试数扩大通过率。有限样本零误报必须写样本量，不能宣称普遍零误报。
