# P1-04：规则与模型持续回归开发任务书

日期：2026-09-06。状态：待实施与实测。优先级：产品 P1。

前置：[总纲](README.md)、[P0-02 基准契约](../wdsp-p0/P0-02_SECURITY_PERFORMANCE_BENCHMARK.md)、[P0-04 最终处置](../wdsp-p0/P0-04_DECISION_SCOPED_EXCEPTIONS.md)。本任务先完成 S1 的工具与前测，再在 S5 完成全部门禁与回退验收。

## 1. 目标与不包含的内容

让每次规则、API 模型或相关执行代码变化都能回答：原来能识别的攻击是否仍被识别，正常业务是否新增误报，实际处置是否正确，以及候选版本是否具备发布和回退证据。

交付固定语料、真实回放、前后版本逐例对比、CI 分层运行、证据登记、发布门禁和回退演练。复用 P0-02 的隔离、运行计划、性能采集和报告结构；本任务不另建一套性能平台，不自动修改生产规则，不把自动学习或大模型判断当作样本真值。

## 4. 语料与样本真值契约

### 4.1 版本化样本

语料 manifest 与用例定义采用版本化 JSON schema，拒绝未知 schema 主版本、重复 ID、路径越界和无法解析的断言。每条样本至少包括：

| 字段 | 约束 |
|---|---|
| `case_id`、`case_version`、`content_sha256` | 稳定 ID；请求、标签或断言发生语义变化必须升用例版本 |
| `family`、`tags`、`criticality` | 检测类别、适用模块、是否强制，不以规则命中反向生成类别 |
| `truth`、`truth_reason` | BENIGN / ATTACK / UNKNOWN，附人工核验依据；UNKNOWN 不进入准确率分母 |
| `source`、`license`、`authorization` | 自建合成或明确可使用的来源；不复制竞品代码与私有测试数据 |
| `scope`、`prerequisites` | 能力范围、应用/角色、协议、必要依赖及独立环境条件 |
| `steps`、`seed`、`reset_plan` | 单请求或有序业务流程、随机种子及状态重置策略 |
| `expectations_by_profile` | 各模式预期 findings、实际动作、源站是否收到以及业务副作用 |
| `evidence_requirements` | 必需访问日志、安全事件、最终处置、响应内容及受控源站计数 |
| `dataset_partition` | TRAIN / VALIDATION / HOLDOUT，分区不可由当前被测模型自行决定 |

期望动作按实际能力填写。观察模式下发现攻击并放行可为正确；被动 Agent 的记录不能作为在线阻断证据。对脱敏动作必须校验最终输出内容，不能只检查事件里出现 MASK_RESPONSE。

### 4.2 首批覆盖与更新纪律

首批语料至少覆盖以下类别，每类同时包含适用的正常样本、恶意样本和边界样本，逐项列出数量；不得只有攻击集：

- WAF：项目声明支持的注入、路径、协议边界，以及合法 SQL/代码文本、Unicode、上传和复杂表单。
- API：参数类型与范围、模型版本、响应敏感字段、对象/身份边界、多步骤行为和合法业务变化。
- 可信身份与例外：P0-03 的无 Token、有效与无效凭据；P0-04 的精确作用域、到期、发布版本与实际执行。
- Bot：P1-02 的正常浏览器、无脚本、真实自动化客户端、挑战重放和挑战通过后仍触发其他防护。不能将所有自动化客户端预标为攻击。
- 采集与关联：P1-03 的请求单侧、HTTP/2 多路复用、gRPC 元数据、WebSocket 握手和重放去重；P1-01 的真实安全/APM 关联与缺数据状态。

模型学习只消费 TRAIN。HOLDOUT 不输入自动学习、模型确认或阈值调优流程；对持久化学习缓存、历史基线和在线计数器也检查隔离。不得运行后自动更新 expected/golden，让当前结果变成新真值。新增误报与漏报需经来源核实后加入固定回归集，保留失败版本和修复版本。

对于历史已知漏报，报告持续列出，不能因为“前后相同”算作通过；属于当前强制能力范围则阻止阶段验收。未声明能力的探索样本单列，不能静默移除失败样本后缩小分母。调整强制范围须形成可审查的新计划，并保留旧计划。

### 4.3 有状态回放与隔离

每条多步骤用例在独立应用/账号/对象和限定的 Valkey 命名空间中执行，记录请求顺序、等待条件、并发屏障与结束状态。重置动作仅作用于本 run_id，禁止全局 FLUSHALL、删除共享表或重置其他运行的学习状态。

动态 JWT、挑战 nonce、证书与时间窗在本轮生成，固定可复现的业务输入与生成参数；不要复用已经过期的 Token 或提前算好的挑战结果。时钟、限流计数、学习预热和后台任务均属于运行计划。多路复用/竞态用例保留实际调度和事件证据，单次串行成功不能替代并发验收。

## 5. 前后版本比较与正确性判定

### 5.1 比较对象

基线与候选各自记录源文件清单哈希、二进制/镜像 digest、编译器版本、规则包及单规则摘要、模型及运行时产物摘要、有效配置、节点和授权配额。相同语料、profile、负载、环境与采样设置下做配对比较。

只改变规则时必须固定执行代码；只改变模型时固定其他规则与阈值；同时升级代码和策略时标记为组合版本比较，不将变化归因于单条规则。新增能力没有旧基线时建立新 profile，回归百分比显示 N/A。

在候选隔离环境编译和发布完整有效快照，等全部测试目标节点 ACK，再执行回放。数据库草稿、发布任务创建成功和部分节点生效都不能代替该条件。快照中敏感值只以受控内容摘要或引用描述，证据不包含密钥本身。

### 5.2 判定器

判定器同时核对可信 request_id、应用、执行节点、实际版本和原始证据。客户端任意指定的 X-Request-ID 不作为唯一关联依据；合成业务可通过受控测试字段记录用例 ID，再与网关生成 ID 对账，该字段不具有授权作用。

必须区分：规则命中、统一 finding、API final_action、网关 final_decision、HTTP 结果和源站业务副作用。源站返回 403、前置 CC 返回 429、响应中出现关键字均不能单独证明目标攻击被指定模块正确处理。ABORTED、ERROR、PENDING_CORRELATION、UNKNOWN 不可默认转为安全通过；等待结束仍缺证据则不通过。

按 P0-02 分别计算检测误报、拦截误报、检测漏报与拦截漏报；逐例列出新增正确命中、新增误报、丢失检测、动作变化、源站变化与不可比较原因。分母为满足适用范围且实际执行有效的样本，同时展示计划数、有效数和缺失数；执行不完整时不授予完整通过结论。分母为零显示 N/A。

### 5.3 门槛

安全与性能门槛复用 P0-02 的预登记规则：强制用例全部满足断言，新增正常业务误拦截为 0；同 profile 的吞吐、P99、错误、资源与持久化事件完整性使用同一已冻结计划。不要在本文另定一套较宽阈值。

每类独立显示结果，不能用更多简单通过用例掩盖某个强制绕过。性能波动按原计划补足有效重复和环境验证，保留全部运行；不能只保留最快的一次。一次 PR smoke 不承担 72 小时长稳，发布阶段仍须引用与候选构建匹配的 P0 最终长稳证据。

## 6. 持续运行与不可变证据

### 6.1 CI 分层

| 层级 | 运行内容 | 门槛 |
|---|---|---|
| PR / 推送检查 | 语料/schema 校验、变更模块单元及接口测试、固定安全 smoke、核心正常业务 | 固定核心集始终执行；路径过滤只能增加相关集，不能完全跳过核心安全检查 |
| 定期完整回归 | 全量声明能力、规则/模型候选对比、适用 P1 浏览器/协议/APM 场景 | 所需专用环境可用；强制项缺环境显示 BLOCKED，汇总检查不变绿 |
| 候选发布 | 完整正确性、P0 性能/长稳/恢复、规则和模型回退 | 证据绑定本次候选及实际配置；不接受历史截图或另一构建的结果 |

在仓库工作流中配置定期回归，不创建与此无关的桌面提醒。枚举现有多个 Go 模块以及前端检查；逐项保存执行数和 SKIP。正式 Agent 构建不得添加 shim，真实 K8s、OTel 数据面与网关集成不得被 Mock 替换。

不可信 PR 代码只运行在隔离、无发布权限和无证据签名私钥的执行器。受信证据签发只能来自受保护的独立验证步骤：它从固定提交构建、执行测试并核验产物，不能读取 PR 提交的 PASS JSON 直接盖章。即使代码位于内部仓库，也不得把任意测试进程与签名私钥放在同一无隔离权限域。

### 6.2 证据包

每轮保存不可覆盖的 manifest、运行计划、语料与构建摘要、实际配置差异、节点 ACK、逐例结果、脱敏请求/响应摘要、日志关联、性能原始分布、故障时间线和生成报告。全量、smoke、长稳和恢复使用独立证据类型，引用关系可追溯。

结果记录统一使用 PASS / FAIL / SKIP / BLOCKED / NOT_RUN。生成报告后修改任一必需文件必须导致摘要校验失败。清理过期原始证据后将报告标记证据不完整，不能继续支撑新发布；失败运行不能被同 run_id 的成功运行覆盖。

为了让后端门禁信任来源，**新增约定**使用离线可验证的报告签名：受控验证服务以 Ed25519 对版本化 manifest 的确定编码字节签名，签名和 key_id 独立封装；manifest 包含用例结果摘要、全部必需文件哈希、构建/计划/语料/配置指纹、运行级别和时间。固定 schema 与字节编码，拒绝重复 JSON 键、未知签名算法和未登记 key_id；不要自行设计加密算法。

公钥由部署管理员登记，私钥独立注入验证服务，不进入仓库、报告或被测容器。签名只证明来源与完整性，不能证明测试结论正确；验证服务仍须检查真实执行、证据数量和判定器输出。密钥撤销后历史报告保留，但不能再作为新发布的可信凭据。

## 7. 后端契约与发布门禁

### 7.1 证据登记与权限（新增约定）

优先复用 P0-01 已实现的证据存储；如不存在，提供双方共用的受控本地存储适配器，不引入新的外部服务。S0 冻结存储对象 ID、写入归属、流式哈希、限额、保留期与只读读取接口。文件必须先登记并验证哈希，未上传完整的报告只能处于待验证状态。

新增最小管理 API，沿用现有鉴权、响应封装、CSRF 与审计：

| API | 权限（新增） | 行为 |
|---|---|---|
| `GET /api/v1/security/regressions` | `security_regression.read` | 按候选指纹、时间、级别、状态分页，默认 20、最多 100 |
| `GET /api/v1/security/regressions/{id}` | `security_regression.read` | 返回摘要、逐例分页入口、可比较状态与门禁理由 |
| `GET /api/v1/security/regressions/{id}/cases` | `security_regression.read` | 分页返回用例差异；禁止一次返回全部原始正文 |
| `POST /api/v1/security/regressions/imports` | `security_regression.import` | 通过已上传的受控对象 ID 登记 manifest、签名及证据，不执行测试命令 |
| `GET /api/v1/security/regression-policy` | `security_regression.read` | 查询门禁模式、要求的级别/语料版本与证据有效期 |
| `PUT /api/v1/security/regression-policy` | `security_regression.policy` | 校验 expected_version；修改留审计；并发冲突 409 |

导入请求只含已登记对象 ID，不接收任意 URL、服务器文件路径、压缩包或 shell 命令；不得由后端访问用户指定远程地址。建议请求上限 1 MiB，manifest 文件上限 4 MiB，用例结果拆为有大小与数量上限的对象分块，导入逐块校验。大体积性能文件使用流式存储，不能全量读入内存。具体总量上限在 S0 按语料规模冻结，缺省不得无限制。

同 run_id、同 manifest 哈希重复导入幂等；同 run_id 不同内容返回 409 并审计。校验签名、来源、schema、全部必需对象哈希、执行数量、用例唯一性及结果一致性；客户端提交 `status=PASS` 不能直接成为后端通过状态。未知/越权对象 ID 不能泄露原始文件。审计仅记录摘要与引用。

数据库迁移保存不可变运行摘要、用例索引/差异、证据对象引用、验证结果、策略版本以及发布任务引用；候选指纹、run_id、case_id 加适用唯一约束。导入失败不残留可用的半份报告。原始大文件不直接塞进数据库结果行。

### 7.2 服务端强制入口

新增门禁模式 OFF / OBSERVE / ENFORCE，建议默认 OFF，界面明确未强制；OBSERVE 计算并记录结论，ENFORCE 才拒绝不满足条件的新发布。启用/降级门禁需要专用策略权限及审计，不向普通发布请求开放 `skip_gate` 参数。

门禁在现有发布器中、候选编译完成后且发往节点前执行。证据必须匹配完整的安全相关候选产物、执行构建、编译器、语料/计划及门禁策略版本。非安全配置差异允许复用的字段白名单必须在 S0 逐项证明与回放无关，不能笼统忽略应用配置。随机时间戳、运行 ID 等非语义字段的规范化方式也须版本化，禁止为了命中旧证据任意删除字段。

建议证据有效期 7 天，可按部署策略收紧；相关内容变化立即失效，不等待到期。缺失、过期、撤销、强制用例不完整或验证失败均阻止 ENFORCE 发布。门禁依赖不可用时返回明确失败，不能静默放行。排队后正式执行前再次核对快照和证据绑定，防止检查后修改配置；必须发送已经检查的那份不可变快照。

规则启停、自定义规则更新、模型激活及运行时发布最终都走此入口。复用现有模型接口与权限：`POST /api/v1/api-security/models/{id}/activate` 和 `POST /api/v1/api-security/runtime-policies/{id}/rollback` 使用 `api_model.activate`；模型 diff/运行时查询使用 `api_model.read`。现有模型生命周期可以保存候选或审核结果，但不能在门禁失败时对外报告网关 ACTIVE；处理数据库变更与发布失败之间的补偿和状态映射。

通过门禁只代表允许开始发布。各目标节点 ACK、失败、超时与实际版本分别保存；部分生效必须显示部分状态，不把主节点成功当作整组完成。发布记录引用不可变的回归报告 ID 与哈希，另外保存最终节点结果；不能为追加发布状态而修改已签名 manifest，便于追溯实测对象和上线对象是否一致。

### 7.3 回退

复用当前运行时策略回退及配置发布流程，以新的发布记录恢复已知良好内容，保留全部历史。不能覆盖失败版本或把“数据库恢复成功”当作流量已恢复。

CI 故障或候选误报时，仍允许具有现有回退权限的操作者恢复本部署曾实际生效、证据完整且与当前执行器兼容的已知良好快照。这个受限通道只接受服务器历史对象 ID，禁止夹带编辑、任意新快照或绕过身份/权限；记录恢复理由、来源证据和所有节点结果。规则/模型回退不能自动解决二进制或数据库不兼容，须验证兼容矩阵并另行执行对应升级回退流程。

普通证据有效期不能阻断上述已知良好内容的应急恢复，但摘要损坏、已撤销信任或执行器不兼容仍需明确阻止并给出具体原因。恢复后在隔离环境复跑关键正常/攻击集，核对节点有效版本、真实业务恢复和状态计数；不得自动把失败候选重新发布。

## 8. UI / UX 要求

在现有规则、模型 diff 和配置发布入口展示“当前生效版本 → 候选版本 → 对应回归 → 发布结果”，优先增加详情与跳转，避免新建重复操作台。

列表显示运行级别、计划/实际/缺失数量、构建/策略指纹、数据新鲜度与是否可用于当前发布。无基线、不可比较、强制项跳过、证据已清理、候选已变化和部分节点生效均有文字原因和恢复动作；不能只显示一个绿色通过百分比。

差异页可按新增误报、丢失检测、动作变化和类别筛选；逐例显示前后预期/实际、最终执行模块、源站结果与脱敏证据。保留筛选、页码和返回上下文，长 Payload 用纯文本和受限展开，缺权限不泄露样本内容。发布被拒时列出确切缺失项和重新回归入口；点击不会静默运行压测或修改生产规则。

## 10. 必须通过的验收用例

以下 26 项均为强制验收；涉及真实发布、协议、APM 和 CI 信任边界的用例不能只用单元测试替代。

| ID | 操作/条件 | 预期 |
|---|---|---|
| REG-001 | 空语料、重复 ID、非法 schema、错误数量或缺失必需文件 | 预检/验证失败，不生成完整通过 |
| REG-002 | 修改请求、真值、期望或原始结果后复用旧哈希 | 摘要不匹配；保留原运行，必须生成新用例版本/运行 |
| REG-003 | 全部正常、全部攻击、UNKNOWN 和零分母分类分别执行 | 计数、范围和 N/A 正确；不能伪造准确率 |
| REG-004 | 源站返回 403、CC 提前 429、目标规则未命中 | 不判为目标防护正确；能定位真实执行模块 |
| REG-005 | 同一攻击执行 OBSERVE 和 PROTECT | 检测与处置独立判断；观察放行不算阻断漏报 |
| REG-006 | 响应 MASK_RESPONSE 存在但实际输出仍有合成敏感值 | 回归失败，不能只根据动作字段通过 |
| REG-007 | P0 JWT、作用域例外、白名单及 Bot clearance 联合请求 | 可信身份与最终防护按各任务断言执行，无跨模块放行 |
| REG-008 | HOLDOUT 与学习缓存混入训练、运行后自动更新 expected | 检查失败；训练隔离，旧失败与真值版本保留 |
| REG-009 | 两个 run_id 并发执行多步骤、限流和状态重置 | 流程可复现且相互隔离，无全局清理 |
| REG-010 | 基线和候选出现额外配置差异、执行器变化或节点未 ACK | 不能给出同配置可比结论；缺生效证据阻止正式执行 |
| REG-011 | 历史强制漏报保持不变，其他类别通过率提高 | 仍失败，平均值不能覆盖强制缺陷 |
| REG-012 | 性能抖动、重复不足、分位数平均或使用别的 profile | 比较无效；按 P0 计划处理并保留全部运行 |
| REG-013 | 强制用例 SKIP、零执行、某嵌套模块漏跑或环境缺失 | CI 汇总不通过，真实状态与缺失项可见 |
| REG-014 | 只有 BAS 分类映射或 FTW 静态文件，没有真实回放 | 不计为执行数/检出率；报告说明来源与范围 |
| REG-015 | 未授权读/导入/改门禁，无效参数及并发修改 | 401/403、校验错误、409 符合现有响应约定；写操作有审计 |
| REG-016 | 伪造 PASS、未知/撤销签名 key、修改 manifest 或对象 | 后端拒绝信任，不登记可用通过结果 |
| REG-017 | 重复导入、同 run_id 异内容、越权 ID、URL/路径输入、超限对象 | 幂等或 409；无 SSRF、路径访问、内存失控与半份可用报告 |
| REG-018 | 不可信 PR 修改脚本/输出并尝试获得签名或发布权限 | 无私钥/发布权限；受保护验证不信任提交的结果文件 |
| REG-019 | ENFORCE 下缺失/过期证据、依赖不可用、客户端传 skip_gate | 新发布被拒且原因可见；不能改变权限与失败语义 |
| REG-020 | 门禁通过后修改配置、模型、规则或队列中的发布对象 | 正式发送前重新核对；只发送已验证快照，无检查后替换 |
| REG-021 | 发布一节点成功、另一节点超时或拒绝 | 页面和审计显示部分生效及各节点版本，不伪报整体成功 |
| REG-022 | CI 不可用时回退到本部署已知良好内容，再尝试夹带修改 | 合法兼容恢复可执行；夹带/损坏/不兼容被拒；真实节点与业务恢复可核对 |
| REG-023 | 报告空/失败/不可比较/已过期，长文本和恶意 HTML，窄屏键盘操作 | 原因、跳转、上下文和可访问性正确，无脚本执行与敏感数据泄露 |
| REG-024 | 目标切换为共享/外部地址、恶意重定向，执行中断后清理 | 攻击/压测不越界；只清理本 run_id 资源并保留证据 |
| REG-025 | 完整 P1 构建运行全量规则/模型、真实 Agent/APM/Bot 和 P0 发布级检查 | 计划与实际数量一致；所有强制断言满足，发布证据绑定当前构建 |
| REG-026 | 另一开发者用固定提交、镜像、语料和计划复跑并回退 | 得到可比较结果；失败可定位、回退可执行，限制有记录 |
