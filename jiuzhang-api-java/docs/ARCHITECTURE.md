# API 安全核心架构

## 数据流

```text
HTTP 接入
→ 有界请求体读取
→ 路径归一化与协议识别
→ 凭据指纹和可选 JWT 验签
→ 有界行为计数
→ JSON / FORM / XML 一次解析
→ 敏感数据、正式模型、授权关系检测
→ 统一请求决策
→ HTTP 源站转发
→ JSON 响应检查与脱敏计划
→ 统一响应决策与执行
→ 安全事件、资产发现和候选学习
```

所有检测器只追加 `Finding`。`DecisionEngine` 是唯一计算最终动作的位置，优先级为限速、阻断、响应脱敏、观察、放行。OFF 直接放行；OBSERVE 将阻断资格降级为观察；PROTECT 才执行阻断或脱敏。

## 数据最小化

请求参数值只存在当前请求上下文中。事件使用归一化路径，不保存原始 Query；客户端 IP 经 HMAC 转换为来源指纹；身份指纹由凭据派生，但 IP 不会冒充身份。JWT 未验签时主体和角色字段保持为空。证据只包含字段名、位置、规则类型和约束名称。

候选模型仅记录类型与统计约束，不保存原始参数值，也不会自动成为正式模型。含有任何检测信号的响应不进入学习，以减少攻击和异常样本污染。

## 资源边界

- 请求体和响应体均有配置上限；
- JSON 限制输入长度、嵌套深度和节点数；
- Query 参数、XML 节点、请求路径段、敏感值求值次数均有限制；
- 行为窗口和候选端点有容量上限；
- 事件文件同步落盘，内存事件队列最多保留 5000 条；
- 管理接口只读且只能监听回环地址。

## 故障语义

配置或模型非法时拒绝启动。命中阻断规则时不联系源站。响应脱敏失败记录 `response.mask_failed` 并保留原响应，不伪装脱敏成功。事件写入失败记录进程错误并累计 `event_write_errors`，但不反向伪造业务响应。当前实现为单进程，重启后内存限速与候选模型清零。
