# 独立实现架构

## 设计目标

本实现面向单节点、直接部署的 Web 请求防护场景。优先保证数据边界清楚、资源消耗可限制、故障信息可观察，并为后续拆分管理面保留接口。它不是现有 Go/Caddy 模块的语法翻译，也不复用其模块结构。

## 请求路径

```text
TCP 接入
  → 生成本次请求标识
  → 根据连接来源决定是否采纳代理地址链
  → 允许/拒绝网段判断
  → 有界固定窗口限速
  → 在配置上限内读取请求体
  → 多轮百分号解码与签名匹配
  → 按 off / observe / protect 形成处置
  → 重建转发头并删除逐跳头
  → 请求发送至配置的唯一源站
  → 响应体以流形式返回客户端
```

白名单只改变地址访问控制和限速结果，不跳过体积检查与攻击检测。这样可以避免“可信地址”配置意外变成完整的防护旁路。

## 模块职责

### 配置模型

TOML 直接反序列化为强类型结构，未知字段会导致启动失败。监听器、网段、URL、数值上下限均在创建服务前校验。配置中的源站只能使用 HTTP 或 HTTPS，不允许把凭据放入 URL。

### 地址识别

非可信连接来源的代理头会被忽略。可信来源的地址链从右向左检查，取第一个不属于可信代理网段的地址；空值、非 IP、超过 16 个节点或超过 2048 字节的链回退到连接来源并记录事件。发送给源站的地址头由网关重新生成，而不是原样透传客户端提供的值。

### 检测器

检测器由少量内嵌签名构成。每个目标最多进行三轮百分号解码，解码后的副本仅用于匹配，不改变转发给源站的原始 URI 和请求体。Rust `regex` 不提供回溯表达式，避免使用灾难性回溯规则。相同规则在一个请求内只产生一条事件。

### 限速器

每个客户端地址保存一个固定窗口。表容量由配置限制；只有容量满时才清理过期项，避免每次请求都扫描全部地址。容量满且没有可清理项时，新地址收到 429。该算法是单进程实现，重启后计数归零，不能在多个实例之间共享。

### 事件与指标

事件采用一行一个 JSON 对象。目标 URI 的查询值全部脱敏，控制字符被替换，长度有上限；不记录请求体。文件写入失败会输出进程错误日志，但不会让源站请求失败。指标使用原子计数器，只暴露聚合数字。

### HTTP 转发

请求体按配置上限缓冲，以便在转发前检查。源站响应不整体缓冲，而是流式返回。客户端与源站之间的重定向不会由 HTTP 客户端自动追随。系统代理环境变量被禁用，源站连接只使用明确配置的目标。

## 当前故障语义

| 场景 | 行为 |
|---|---|
| 命中拒绝列表 | 403，不联系源站 |
| 超过限速或客户端表容量 | 429，不联系源站 |
| 请求体无法读取或超过上限 | 413，不联系源站 |
| `protect` 下命中攻击规则 | 403，不联系源站 |
| `observe` 下命中攻击规则 | 记录事件并继续转发 |
| 源站连接失败或超时 | 502，响应不包含源站错误中的 URL |
| 事件文件写入失败 | 主请求继续，进程日志记录错误 |
| 配置无效 | 进程拒绝启动 |

## 后续扩展方向

下一阶段应先完成 HTTPS 接入与多站点路由，再考虑规则热更新。管理写接口需要单独引入身份认证、授权、CSRF 防护和操作审计，不能把当前回环只读接口直接改为公网管理面。多实例部署前，应重新设计共享限速和事件存储，而不是在本地文件上叠加网络锁。
