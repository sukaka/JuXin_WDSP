# 内置检测规则

本版本使用独立的轻量签名集，规则编号以 `JZN` 开头，不声称兼容 OWASP CRS，也不复制 CRS 规则文本。

| 编号 | 类型 | 典型特征 | 默认严重度 |
|---|---|---|---|
| `JZN-SQL-001` | SQL 注入 | 联合查询、布尔恒真条件、时间延迟函数 | high |
| `JZN-XSS-001` | 跨站脚本 | 脚本标签、JavaScript 协议、部分事件属性、框架页标签 | high |
| `JZN-CMD-001` | 命令注入 | 命令分隔符后的常见命令、危险变量展开、反引号执行 | critical |
| `JZN-PATH-001` | 路径穿越 | 连续的父级目录跳转及编码变体 | high |
| `JZN-FILE-001` | 文件包含 | 常见敏感系统路径和包装器协议 | high |
| `JZN-PROTO-001` | 协议异常 | 解码后的空字节 | medium |
| `JZN-PROTO-002` | 协议异常 | TRACE、TRACK、CONNECT 方法 | medium |
| `JZN-SCAN-001` | 扫描器特征 | User-Agent 中的部分自动化扫描器名称 | medium |

访问控制和资源限制使用独立编号：`JZN-ACL-002`、`JZN-RATE-001`、`JZN-SIZE-001`、`JZN-PROXY-001`。

## 匹配范围

规则检查 URI、请求体以及除 Authorization 和 Proxy-Authorization 外的可读请求头。单个请求头的检查长度最多为 65536 个字符，请求体上限由配置决定。URI、请求体和请求头分别进行最多三轮百分号解码，`+` 在检测副本中按空格处理。

这些规则是攻击线索而非完整语义分析。富文本、技术文章、代码编辑器等场景可能出现误报；上线前应先使用 `observe` 收集业务样本，再切换到 `protect`。当前版本没有规则例外管理接口，需要调整源代码中的签名并重新运行测试、构建和发布。

## 事件字段

每条事件包含时间、事件 ID、请求 ID、客户端地址、方法、脱敏目标、处置、规则编号、类型、严重度和处置状态。事件不包含规则命中的原文，因此调查时只能依靠请求 ID 与规则类型关联，不应把该文件当作完整流量审计。
