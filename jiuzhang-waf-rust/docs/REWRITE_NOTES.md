# 独立重构与登记材料说明

## 本次采用的方式

本目录从能力目标出发重新组织代码，使用 Rust 异步 HTTP 服务和内嵌检测器。没有复制现有网关的 Go 文件、Caddy 配置生成器、Coraza 规则包、数据库结构、前端页面或接口定义。请求编排、配置模型、事件字段、规则编号、测试数据和文档表达均在新目录中单独编写。

当前交付是第一阶段技术底座。它证明了不依赖容器的原生路线可行，但并不覆盖原系统的全部业务功能。后续模块也应按功能边界重新设计，避免把不同语言当作对原文件逐句转换的工具。

## 关于“重合度”

更换编程语言本身不构成独创性保证，也不能承诺软件著作权登记、代码查重或产品说明审查一定得到某个结果。登记材料是否相似通常还取决于目录结构、命名、流程图、界面、接口、文字表达以及审查方采用的方法。

更稳妥的做法是：

1. 保留需求分析、架构决策、提交记录、测试记录等独立研发过程证据；
2. 对新旧代码和第三方组件分别做来源与许可证核查；
3. 产品说明按本实现的真实能力撰写，不沿用尚未实现功能的宣传内容；
4. 对仍被认为相似的表达进行实质性重写，而不是只替换产品名或变量名；
5. 正式申报前由知识产权专业人员审核具体材料和当地要求。

## 本阶段材料边界

`README.md`、架构说明、检测规则说明和运维说明均以当前 Rust 实现为依据。原系统的人事权限、报表、集群、前端、数据库、Bot、API 动态防护等说明没有被搬入本项目，因为本阶段没有这些实现，也不应在登记材料中把它们描述为已完成。
